# refine-style（根拠インデックス）

`writing-guides/refine-style.md` の各ルールを支持する記事の索引。**analyzer 専用。`author-style-writer` は読まない。**

- `##` は記事 slug（記事名ではない）をキーとする。この階層は slug の予約とし、注記に使わない。
- 値はその記事から採れた支持ルール名のリスト。括弧内は修正前後のコミット対。
- 反例は `※` で注記する。
- 確度は導出値である。ルールを支持する記事数・記事タイプの幅は、このファイルを数えて算出する。
- 記事を再分析するときは、当該記事のブロックを丸ごと消して書き直す（他の記事のエントリには触らない）。

**根拠の性質に関する重要な注意**

本来 `refine-style.md` は「AI草稿と人間による編集との差分」から修正傾向を抽出するファイルである。ただし本ガイドの根拠には、性質の異なる2系統が混在する。この違いが各ルールの確度と適用範囲を左右するため、先に区別しておく。

- **実際のAI草稿→人手編集の差分**：`[ai-draft]` を含むコミット（`〜 [ai-draft]` / `〜：修正内容 [ai-draft]`、後方互換の使役形「〜：草稿を書かせた」、および規約導入前後の「〜：著者スタイルガイドに沿ってメモから草稿を書き直し」のようにスキル生成であることを明記したコミット）でAI生成文が記録され、その後に人手編集が重なっている記事から採れる差分。この系統に限り、AIらしいメタ足場・自己言及・冗長な再要約・定型表現の除去を、本ファイル本来の趣旨どおり修正傾向として扱える。
- **著者自身の自己改稿（下書き→推敲）の差分**：AI草稿が存在せず、著者が段階的に手書きした下書きから完成稿への推敲を追った差分。ここから採れるのは、箇条書きメモの散文化、因果・目的の補足追加、記法・用語の統一といった著者自身の推敲操作に限る。対象となるAI草稿がないため、「AI特有の定型表現の除去」はこの系統では根拠にできない。

この2系統を踏まえ、次の制約を置く。

- **AI特有の定型表現（メタ足場・自己言及・冗長な再要約）の除去は、実際のAI草稿差分がある記事の根拠に限って扱う**。自己改稿のみが根拠の操作へは一般化しない。
- 根拠が単一シリーズ・近接時期に閉じる傾向は、確度を **条件付きの傾向以下**に抑える。
- 各根拠のコミット参照は、修正前後の対応を示す最小限の識別子として、このファイルの各エントリにのみ記載する。差分の生ログは含めない。
- 根拠が単一のコミット・単一の記事に閉じる操作は、主要ルールにせず `pending/refine-style.md` へ分離する。
- AI草稿マーカーを持つコミットが存在しない記事群からは、AI草稿→人手編集の修正傾向は確認できない。その場合は無理に推定せず、根拠なしとして扱う。
- **差分の増減行数を、圧縮・加筆の量的な根拠にしない。** 著者は箇条書きのメモをHTMLコメントとして本文中に残したまま散文化させ、公開時の推敲コミットでそのコメントを一括削除する運用（メモ→草稿→推敲）をとることがある。この場合、削除行数の相当部分がメモであり、散文の圧縮量とは対応しない。`draft: true` の除去も同様にメタデータ操作として文体修正から分離する。

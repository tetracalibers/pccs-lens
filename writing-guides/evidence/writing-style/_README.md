# writing-style（根拠インデックス）

`writing-guides/writing-style.md` の各ルールを支持する記事の索引。**analyzer 専用。`author-style-writer` は読まない。**

## 形式

1記事1ファイル。ファイルパスがそのまま記事 slug に対応する（`cg/basics/anti-aliasing.md` ＝ `/cg/basics/anti-aliasing`）。

```markdown
分析時点: `d8bd3563`
記事タイプ: 概念解説

- WS-004（末尾を結果要約「なめらかに見えるようになります」で閉じる）
- WS-010（前提記事へリンクし前回の欠落を述べてから問いへ）
  ※ WS-032：スーパーサンプリングは前手法の限界提示を伴わず、限界駆動が弱い
```

- **`- <ルールID>（該当箇所）` の行だけが支持である。** 括弧内は本文中の該当箇所を短く。
- `※` 行は反例・除外の注記で、**支持には数えない**。「反例」はその構成が働かなかった箇所、「除外」は記事タイプ由来・媒体規約由来などで根拠に数えない箇所。直前の支持行に紐づけて置く。
- ルールはIDで参照する。ルール名を書かないのは、短縮形で書かれると機械照合が壊れるため（ID は改名しても変わらず、廃止しても欠番として残る）。
- `分析時点` は、分析した本文のコミット（`app/src/routes/<slug>/+page.svx` を最後に変更したコミット）の短縮SHA。**記録した SHA が現在の最終更新コミットと違えば、その記事は分析後に改稿されている。** 再分析の対象を洗い出すときはこの比較で判定する。同じ記事なら4観点で同じ値になる。
- `記事タイプ` は分析時に分類した種別。移行で作られたファイルは `未記録` のままで、再分析した時点で埋まる。

## 支持記事数の数え方

確度は導出値である。ルールを支持する記事数は次で求める。

```sh
node scripts/style-evidence-tally.mjs --aspect writing-style --full
grep -rlE '^- WS-012' writing-guides/evidence/writing-style/ | wc -l   # 1ルールだけ見るとき
```

`※` 行を数えないよう、grep では行頭の `- ` を含めて照合する。

記事を再分析するときは、**当該記事のファイルだけ**を書き直す（他の記事のファイルには触らない）。

## 根拠の性質に関する注意

`writing-style.md` は「どこに何が置かれるか」という配置と構造を扱うため、根拠は「その要素がその位置にある／ない」という形で確認できる。一方、配置の型そのものは日本語の技術文書一般と重なるため、確度の判定では次を区別する。

- **著者固有性のある選択**：型の存在ではなく、その型をどこまで徹底するか（例：総論→各論の予告文を必ず一文立てる、前節の到達点を明示的に受け直す）。「総論→各論」「定義先行」「単純→複雑」「末尾要約」などの型自体は普遍的な教授原則・構成術であり、確度を上げる根拠にしない。
- **記法・共有コンポーネント由来**：CardGrid／TermCard／`cols`／`icon`／`:WithGradeTag`／`ankiTitle` に依存する配置、およびプロジェクトの記法ガイドが規定する構成（CGルート記事の前記事振り返り型導入、「用語：説明」箇条書きなど）は、機械的運用と著者判断を切り分けられないため確度を抑える。他媒体では同じ配置意図を別手段で実現する必要がある点も併記する。
- **ジャンル・媒体慣習の交絡**：短〜中規模のリファレンス記事群では総括節が省かれるのが通例であるなど、「不在」の観察は媒体条件による説明を排除できない。異なるジャンル（通史・色の活用分野など）で再確認できた場合にのみ、慣習だけには帰せないと判断する。
- **テーマ主導・記事タイプ主導**：記事タイプ（概念解説／通史／設計プロセス解説／実装解説／数式・法則型）によって型の出入りがある場合は、記事タイプを超えて成立する部分だけを根拠に数える。
- 根拠が単一シリーズ・同一ドメイン・近接時期に閉じる傾向は、確度を **条件付きの傾向以下**に抑える。
- 根拠が1記事1箇所に閉じる観察は、主要ルールにせず `pending/writing-style.md` へ分離する。

## 移行時の注記

このインデックスは既存ガイドの根拠・確度欄から機械的でない抽出を行って作成したもので、**網羅的な記事リストではない**。「配色技法シリーズ10本すべて」「混色シリーズ6本」のように記事を特定せず集約されていた根拠は、本文で個別に名指しされた記事にのみ登録している。各記事を再分析した時点で、その記事のファイルを正しい内容へ置き換える。

このため、**支持記事数が少ないことは根拠が弱いことを意味しない**（登録漏れのことがある）。確度の降格を機械化するときは、そのラウンドで書き直した記事に関係するルールだけを対象にする（`style-evidence-tally.mjs --round`）。

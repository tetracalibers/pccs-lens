# 記事 数式記法ガイド

`syntax-guide.md`（記事 記法ガイド）から、**数式（KaTeX）の記法**と、その表記に関わる**インラインコード `` `code` `` の規約**を切り出したガイドです。対象とする記事も適用範囲も `syntax-guide.md` と同じで、記事本文（`+page.svx`）を書くときは両方に従います。

数式は **KaTeX** でレンダリングされます。インライン・ブロックともに **`$$...$$`** で囲みます（`$...$` 単独のドル記号は数式になりません）。

- ここに無い記法（独自ディレクティブ、`:Anki[]`、見出しの分類タグ、リンク、コードブロック・擬似コード、禁止事項）は `syntax-guide.md` を参照してください。**`:Anki[]` とインラインコードの使い分けだけは `syntax-guide.md`（ルール1）にあります。**
- 何を書くか・どう語るか（構成・語り口・推敲）は、`thinking-flow.md`（思考フロー）・`writing-style.md`（文章構成）・`stylistic-quirks.md`（表現上の癖）・`refine-style.md`（推敲・修正傾向）を参照してください。

## ルール一覧

各ルールには**ルールID**（URLスラッグ風の識別子）が付いています。`/format-math-notation <slug> --rules=<ルールID>` のように渡すと、**そのルールだけ**を整備できます（複数指定はカンマ区切り。**省略すると全ルールが対象**）。

| ルールID | ルール |
| --- | --- |
| `prefer-inline-code` | インライン数式はなるべく使わず、インラインコードで書く |
| `block-math-format` | ブロック数式は段落全体を `$$...$$` にする |
| `block-math-linebreak` | ブロック数式の改行はバックスラッシュ4つ（`\frac` を含むなら8つ） |
| `prime-notation` | プライム記号は `'` を使わず `^{\prime}` と書く |
| `action-no-inline-math` | `:::Action` のテキストではインライン数式を使わない |
| `numbers-in-inline-code` | 数字は必ずインラインコードにする |
| `function-names-in-inline-code` | 数学の関数名もインラインコードにする |
| `no-inline-code-in-labels` | `:Anki[]`・`:Mark[]` のラベルとリンクのテキストではインラインコードを使わない |
| `no-space-around-inline-code` | インラインコードの前後には空白を置かない |
| `space-around-inline-math` | インライン数式の前後には半角スペースを置く |
| `math-enum-comma` | 記号を並べるときは1つのインライン数式にまとめ、カンマで区切る |
| `article-symbol-unify` | 同じ対象を表す記号は、インライン数式とインラインコードを混在させない |
| `sentence-math-unify` | インライン数式を含む文では、数式・変数・関数名をインライン数式に統一する |
| `block-math-symbol-unify` | ブロック数式を説明する文では、その式の記号をインライン数式で書く |
| `math-promotion-style` | インラインコードからインライン数式に直すときの書き方 |
| `inline-math-dfrac` | インライン数式の分数は `\dfrac` で書く |

どのルールIDをどの textlint ルールが検査するかは `app/textlint/README.md` の対応表にあります。

## インライン数式はなるべく使わず、インラインコードで書く

**ルールID**: `prefer-inline-code`

地の文に式を埋め込むときは、**なるべくインライン数式（`$$...$$`）を使わず、インラインコード `` `code` `` で記述します**。

- 例: `$$\frac{1}{2}$$` ではなく `1 / 2`、`$$2dx$$` ではなく `2dx` と書きます。
- **KaTeX でしか表記できない数学記号やギリシャ文字**（`$$\equiv$$`、`$$\times$$`、上付き・下付き文字、ギリシャ文字、`$$[R]$$` のような色記号の慣習表記など）が含まれる場合**のみ**、インライン数式にします。
  - たとえばギリシャ文字の `θ` は、地の文でもインラインコードにせず `$$\theta$$` と書きます。
  - ただし `:::Action` のテキストは例外で、ギリシャ文字もインライン数式にしません（→ `action-no-inline-math`）。

- **インライン数式**（KaTeX が必要なときのみ）: 地の文の中に `$$...$$` を埋め込む。

  ```
  赤 $$[R]$$・緑 $$[G]$$・青 $$[B]$$ の`3`色の光を重ねます。
  ```

## ブロック数式は段落全体を `$$...$$` にする

**ルールID**: `block-math-format`

**ブロック（中央寄せの独立した式）** は、その**段落が数式 `$$...$$` だけ**で構成されるようにします（前後を空行で挟み、`$$` を独立した行に置く）。

```
$$
[X] \equiv R[R] + G[G] + B[B]
$$
```

**複数行の式** は `\begin{align*} ... \end{align*}` を使います（行末の改行の書き方は → `block-math-linebreak`）。

```
$$
\begin{align*}
[X] &\equiv R_1[R] + G_1[G] + B_1[B] \\\\
[Y] &\equiv R_2[R] + G_2[G] + B_2[B]
\end{align*}
$$
```

## ブロック数式の改行はバックスラッシュ4つ（`\frac` を含むなら8つ）

**ルールID**: `block-math-linebreak`

- 複数行の式の**行末の改行は `\\\\`（バックスラッシュ4つ）** で表します（mdsvex のエスケープを通すため2つではなく4つ必要）。
- **`\frac` による分数を含む数式ブロック**では、`\\\\`（バックスラッシュ4つ）で改行すると分数の高さの分だけ行が詰まって見えます。この場合は**行末の改行を `\\\\\\\\`（バックスラッシュ8つ）** にして行間を確保します。

  ```
  $$
  \begin{align*}
  e + \frac{dy}{dx} &> \frac{1}{2} \\\\\\\\
  2dx \cdot e + 2dy &> dx \\\\\\\\
  2dx \cdot e + 2dy - dx &> 0
  \end{align*}
  $$
  ```

## プライム記号は `'` を使わず `^{\prime}` と書く

**ルールID**: `prime-notation`

**プライム記号（`'`）は使わず `^{\prime}` と書きます。** 変換後の座標などを表す `x'`・`y'` を、アポストロフィ `'`（`x'`）で書いてはいけません。mdsvex の smartypants がレンダリング前にこの `'` をカーリークォート `’`（U+2019）に変換してしまい、KaTeX が「LaTeX-incompatible input ... Unrecognized Unicode character "’" (8217) [unknownSymbol]」という警告を出すためです。`^{\prime}` と書けばクォート文字を含まないので変換を受けず、表示結果は `x'` と同じになります。

```
$$
\begin{pmatrix} x^{\prime} \\\\ y^{\prime} \end{pmatrix} = \begin{pmatrix} \cos\theta & -\sin\theta \\\\ \sin\theta & \cos\theta \end{pmatrix} \begin{pmatrix} x \\\\ y \end{pmatrix}
$$
```

## `:::Action` のテキストではインライン数式を使わない

**ルールID**: `action-no-inline-math`

デモの操作を促す `:::Action`（`{fixme}` 付きも同じ）のテキストでは、**KaTeX でしか表記できない記号やギリシャ文字を含む場合でも、インライン数式（`$$...$$`）を使わずインラインコード `` `code` `` で書きます**。地の文の「なるべく」より強い、例外のないルールです。

`:::Action` は地の文ではなく、デモの直前に置く短い操作案内です。KaTeX で組まれた式は字面も高さも地の文と変わるため、一行の案内文に混ぜると浮いて読みにくくなります。

- **ギリシャ文字は Unicode の文字をそのままインラインコードに入れます**（`$$\theta$$` ではなく `` `θ` ``）。

  悪い例:

  ```
  :::Action
  $$r$$と$$\theta$$を変えることで、さまざまな位置を表せることを確認しよう
  :::
  ```

  良い例:

  ```
  :::Action
  `r`と`θ`を変えることで、さまざまな位置を表せることを確認しよう
  :::
  ```

- `≡`・`×` のように Unicode の文字で書ける記号も、同じくインラインコードに入れます。**Unicode の文字1つに置き換えられるもの**（ギリシャ文字、`×`・`÷`・`±`・`≡`・`≠`・`≤`・`≥`・`≈`・`∞`・`→`・`⊂`・`∈`・`∂`・`Σ`・`∫` など）が対象です。textlint がこの置き換えを自動で当てるので、対応表は `app/textlint/lib/math-tokens.js` の `UNICODE_SYMBOLS` が実体になります。
- **添字・分数・行列のように Unicode の文字だけでは書けない式は、`:::Action` に持ち込まず日本語で言い換えます**（`$$f_s$$` を上げる操作なら「標本化周波数を上げてみよう」）。操作を促す一文に式そのものを載せる必要はほとんどありません。
- インラインコードなので、**前後に半角スペースは置きません**（→ `no-space-around-inline-code`）。地の文のようにインライン数式の前後を空ける必要はなくなります。
- 数字はもとからインラインコードなので、そのまま書きます。

このルールは記事全体・文単位の統一ルールより優先します。地の文で `$$\theta$$` と書いている記事でも、`:::Action` の中だけ `` `θ` `` になるのは混在ではありません。

## 数字は必ずインラインコードにする

**ルールID**: `numbers-in-inline-code`

**単体で成り立つかどうかに関わらず、数字は必ずインラインコード `` `code` `` として記述します。**

- `0と1` など、**数値が単体で現れる場合**は、`0` と `1` をそれぞれインラインコードにします。
- `2進数` や `3つの` など、**単語中の数値**も、数字の部分だけをインラインコードにします（`` `2`進数 ``、`` `3`つの ``）。
- `1mm` など、**単位つきの数値**は、単位も含めてインラインコードにします。

この規約は、**インライン数式（`$$...$$`）を含む文でも変わりません**（インラインコードのままにします）。

- 良い例: ``回転角 $$\theta$$ を`0`から`360`度まで動かすと``

## 数学の関数名もインラインコードにする

**ルールID**: `function-names-in-inline-code`

`sin` など、**数学で定義されている関数名**もインラインコード `` `code` `` にします。

- 対象は `sin`・`cos`・`log` のように**数学の関数として定義された名前**です（`abs`・`min`・`max` などプログラミング寄りの名前は、地の文の英単語と衝突しやすいので対象にしていません）。
- 数字と違い、**インライン数式を含む文では関数名もインライン数式に統一します**（→ `sentence-math-unify`）。

## `:Anki[]`・`:Mark[]` のラベルとリンクのテキストではインラインコードを使わない

**ルールID**: `no-inline-code-in-labels`

**`:Anki[]`・`:Mark[]` のラベルと、リンクのテキストの中ではインラインコードを使いません。**
これらに数字や関数名が含まれる場合は、バッククォートで囲まずそのまま書きます。

- **`:Anki[]`・`:Mark[]`**: ディレクティブのラベルはインラインコードとして解釈されないため、そもそも囲めません。
  - 良い例: `:Anki[10YR]`、`:Anki[n色覚]`、`:Mark[2次曲線]`
- **リンクのテキスト**: 記法としては囲めますが、リンクのラベルは装飾を混ぜずひとまとまりで見せるため、囲みません。
  - 悪い例: ``[`2`次曲線](/cg/modeling/quadratic-curve/)``
  - 良い例: `[2次曲線](/cg/modeling/quadratic-curve/)`

## インラインコードの前後には空白を置かない

**ルールID**: `no-space-around-inline-code`

インラインコードと地の文の境界には、半角スペースを入れません。

- 悪い例: `輝度 `255` の白`
- 良い例: `輝度`255`の白`

## インライン数式の前後には半角スペースを置く

**ルールID**: `space-around-inline-math`

インライン数式（`$$...$$`）と地の文の境界には、**半角スペースを1つ入れます**。スペースは `$$` の内側ではなく、**外側**（地の文との間）に置きます。

- 悪い例: `画素値$$i$$をもつ画素の個数を$$h(i)$$と書きます。`
- 良い例: `画素値 $$i$$ をもつ画素の個数を $$h(i)$$ と書きます。`

**インラインコードとは逆のルール**です（インラインコードは前後を密着させます → `no-space-around-inline-code`）。KaTeX で組まれた数式は地の文と字面が変わるため、密着させると語の切れ目が読み取りにくくなります。

例外は次のとおりです。

- **直後・直前が約物（`、`・`。`・`・`・括弧など）のときはスペースを入れません。** 約物自体が切れ目になるため、スペースを足すと不自然に空きます。
  - 良い例: `もとの信号に含まれる空間周波数の最大値を $$f_\text{max}$$、標本化周波数を $$f_s$$ とすると、`
  - 良い例: `（$$T^{-1}$$ は逆行列）`
- 行頭・行末（前後に文字が無い位置）では不要です。
- ブロック数式（段落全体が `$$...$$` のもの）は対象外です。

## 記号を並べるときは1つのインライン数式にまとめ、カンマで区切る

**ルールID**: `math-enum-comma`

数学的対象を並べて挙げるときは、**記号ごとにインライン数式（`$$...$$`）を分けて中黒 `・` で繋がず、1つのインライン数式の中でカンマ `,` で区切ります**。KaTeX で組まれた記号の間に地の文の中黒が挟まると、記号の列がひとまとまりに見えません。

- 悪い例: `両端の点 $$P_0$$・$$P_1$$`
- 良い例: `両端の点 $$P_0, P_1$$`
- 悪い例: `$$R$$・$$G$$・$$B$$ 各成分`
- 良い例: `$$R, G, B$$ 各成分`

- 3つ以上並べるときも同じです（`$$R, G, B$$`）。式そのものを並べる場合も、1つの数式にまとめます（`$$t = 0$$・$$t = 1$$` ではなく `$$t = 0, t = 1$$`）。
- カンマの後には半角スペースを1つ入れます（`$$P_0,P_1$$` ではなく `$$P_0, P_1$$`）。
- まとめたインライン数式の前後の半角スペースは、これまでどおり数式の外側に置きます（→ `space-around-inline-math`）。
- **中黒が繋いでいるのが記号そのものではなく日本語の語句のときは、中黒のままにします。**「$$x$$ 方向に $$a$$・$$y$$ 方向に $$b$$ 進む」「それぞれ $$a$$ 倍・$$b$$ 倍した」のように、並列されているのが記号を含む句であれば、インライン数式を分けたまま `・` で繋ぎます。
- インラインコードで書いた記号や数字の並列は対象外です（`` `0`と`1` `` のように、地の文の言葉で繋ぎます）。

## 同じ対象を表す記号は、インライン数式とインラインコードを混在させない

**ルールID**: `article-symbol-unify`

ある数学的対象を表す記号は、記事全体を通して**インライン数式（`$$...$$`）かインラインコード `` `code` `` のどちらか一方に統一**します。同じ対象を、ある箇所ではインライン数式、別の箇所ではインラインコードで書いてはいけません。

- たとえば、行列をインライン数式で表記する箇所が1つでもあれば、その行列を表す他の箇所もすべてインライン数式で書きます。
- 悪い例: ``$$T^{-1}$$ は`T`の:Anki[逆行列]で``
- 良い例: `$$T^{-1}$$ は $$T$$ の:Anki[逆行列]で`

- **`:::Action` のテキストは、この統一の対象外です。**地の文をインライン数式で書いている記号でも、`:::Action` の中ではインラインコードにします（→ `action-no-inline-math`）。

- **色・記号の慣習**（色彩分野の記事に合わせる）:
  - 色光・色刺激は角括弧つきの大文字で書く: `$$[R]$$`、`$$[G]$$`、`$$[B]$$`、`$$[X]$$`。
  - 混色量・三刺激値は角括弧なしの大文字で書く: `$$R, G, B$$`。
  - 「等色（見た目が一致）」を表す記号は等号 `=` ではなく `$$\equiv$$` を使う。
  - 掛け算は `$$\times$$`、その他は標準のLaTeX記法。

## インライン数式を含む文では、数式・変数・関数名をインライン数式に統一する

**ルールID**: `sentence-math-unify`

**1つの文の中にインライン数式（`$$...$$`）が1つでもあるなら、その文に出てくる他の数式・変数記号・関数名も、インラインコードにせずインライン数式で書きます。**

- 悪い例: ``画素値 $$i$$ をもつ画素の個数を`h`と書きます。``
- 良い例: `画素値 $$i$$ をもつ画素の個数を $$h$$ と書きます。`
- 悪い例: ``傾き`a = dy / dx`を、角度 $$\theta$$ で表すと``
- 良い例: `傾き $$a = dy / dx$$ を、角度 $$\theta$$ で表すと`
- 悪い例: ``位相 $$\phi$$ をずらすと、`sin`の波形が``
- 良い例: `位相 $$\phi$$ をずらすと、$$\sin$$ の波形が`

**数字だけはこの統一の対象外です。**`numbers-in-inline-code` をそのまま守り、インライン数式を含む文でも数値はインラインコードで書きます。

- 良い例: ``回転角 $$\theta$$ を`0`から`360`度まで動かすと``

インラインコードから置き換えた数式・変数・関数名にも、**前後の半角スペースのルールがそのまま適用されます**（→ `space-around-inline-math`）。

判定は**文単位**です。同じ段落の中でも、インライン数式を含まない文では、これまでどおり `prefer-inline-code` に従います。

**`:::Action` のテキストはこの統一の対象外です。**インライン数式にできる記号が含まれていても、`:::Action` の中ではすべてインラインコードで書きます（→ `action-no-inline-math`）。

## ブロック数式を説明する文では、その式の記号をインライン数式で書く

**ルールID**: `block-math-symbol-unify`

ブロック数式（段落全体が `$$...$$` のもの）の意味を地の文で説明するときは、**その式に出てくる記号をインラインコードにせず、インライン数式（`$$...$$`）で書きます**。ブロック数式で組んだ記号と地の文の記号は同じ対象を指すので、表記を揃えます（→ `article-symbol-unify`）。

悪い例:

```
$$
\begin{align*}
x &= a \cos\theta \\\\
y &= b \sin\theta
\end{align*}
$$

この式は、半径`1`の円周上の点の`x`と`y`を、それぞれ`a`倍・`b`倍したものと読むこともできます。
```

良い例:

```
$$
\begin{align*}
x &= a \cos\theta \\\\
y &= b \sin\theta
\end{align*}
$$

この式は、半径`1`の円周上の点の $$x$$ と $$y$$ を、それぞれ $$a$$ 倍・$$b$$ 倍したものと読むこともできます。
```

- 説明の文がブロック数式の直後にあるか少し離れているかは問いません。**その式の記号を指して説明している文**が対象です。
- **数字はここでも対象外です。**`numbers-in-inline-code` のとおり、上の例の `1` はインラインコードのままにします。

## インラインコードからインライン数式に直すときの書き方

**ルールID**: `math-promotion-style`

3つの統一ルール（`article-symbol-unify`・`sentence-math-unify`・`block-math-symbol-unify`）でインラインコードをインライン数式へ直すときは、次のように書きます。

- **添字は波括弧で囲みます**（`` `C_fg` `` → `$$C_{fg}$$`）。添字が1文字のときも同じで、`` `f_s` `` は `$$f_{s}$$` と書きます。`\text` は使いません。
- **プライム記号は `^{\prime}`** にします（`` `x'` `` → `$$x^{\prime}$$`。→ `prime-notation`）。
- **複合語の中の記号も囲みます**（`` `x`軸 `` → `$$x$$ 軸`、`` `x`方向 `` → `$$x$$ 方向`）。数字の「単語中でも囲む」と同じ扱いです。
- **前後に半角スペースを入れます**（→ `space-around-inline-math`）。約物に接する側と行頭・行末は入れません。
- **スラッシュで書いた分数は `\dfrac` で組み直します**（`` `a = dy / dx` `` → `$$a = \dfrac{dy}{dx}$$`。→ `inline-math-dfrac`）。分子・分母の取り方を決める判断が要るので、ここだけは機械的に置き換えられません。

## インライン数式の分数は `\dfrac` で書く

**ルールID**: `inline-math-dfrac`

インライン数式（`$$...$$`）の中で分数を書くときは、**スラッシュ `/` で済ませず `\dfrac` で組みます**。インライン数式の中の `\frac` は地の文の高さに合わせて小さく組まれ、分子・分母が読み取りにくくなるためです。

- 悪い例: `$$y/b$$`
- 良い例: `$$\dfrac{x}{a}$$`

対象はインライン数式の中だけです。

- 地の文にインラインコードで式を書く場合は、これまでどおりスラッシュで書きます（`` `1 / 2` ``、→ `prefer-inline-code`）。
- ブロック数式（段落全体が `$$...$$`）はもとからディスプレイサイズで組まれるため、`\frac` のままでかまいません（改行を `\\\\\\\\`（バックスラッシュ8つ）にするルールはそのままです → `block-math-linebreak`）。

## 仕上げチェックリスト（数式・インラインコード）

本文を書き終えたら、次を確認してください。ここに無い項目は `syntax-guide.md` の「仕上げチェックリスト」で確認します。

- [ ] 数式は、KaTeX でしか表記できない記号やギリシャ文字を含む場合を除き、インラインコードで記述している（インライン数式を多用していない。`θ` は `$$\theta$$` と書く）。`prefer-inline-code`
- [ ] 同じ対象を表す数学記号は、インライン数式とインラインコードを混在させず、記事全体でどちらか一方に統一している。`article-symbol-unify`
- [ ] `:::Action` のテキストにインライン数式を使っていない（ギリシャ文字も `` `θ` `` のようにインラインコードで書き、Unicode で書けない式は日本語に言い換えている）。`action-no-inline-math`
- [ ] インライン数式を含む文では、その文の他の数式・変数・関数名もインライン数式で書いている（数字だけはインラインコードのまま）。`sentence-math-unify`
- [ ] ブロック数式を説明する文では、その式に出てくる記号をインライン数式で書いている（インラインコードにしていない。数字は除く）。`block-math-symbol-unify`
- [ ] 記号を並べて挙げるところは、インライン数式を分けて中黒 `・` で繋がず、1つの数式にまとめてカンマで区切っている（`$$P_0$$・$$P_1$$` ではなく `$$P_0, P_1$$`）。`math-enum-comma`
- [ ] インライン数式の中の分数は、スラッシュ `/` ではなく `\dfrac` で組んでいる（`$$y/b$$` ではなく `$$\dfrac{x}{a}$$`）。`inline-math-dfrac`
- [ ] インラインコードから直したインライン数式で、添字を波括弧で囲んでいる（`$$C_{fg}$$`。`\text` は使わない）。`math-promotion-style`
- [ ] ブロック数式はすべて `$$...$$`（段落全体を数式にしている）。`block-math-format`
- [ ] 複数行のブロック数式は `\\\\` で改行している（`\frac` を含む数式ブロックは行が詰まるため `\\\\\\\\`（バックスラッシュ8つ）で改行している）。`block-math-linebreak`
- [ ] プライム記号はアポストロフィ `'`（`x'`）ではなく `^{\prime}`（`x^{\prime}`）で書いている（smartypants 起因の KaTeX 警告を避けるため）。`prime-notation`
- [ ] 数字は単体・単語中を問わず、すべてインラインコードにしている。`numbers-in-inline-code`
- [ ] 数学で定義されている関数名（`sin` など）もインラインコードにしている（インライン数式を含む文ではインライン数式に統一）。`function-names-in-inline-code`
- [ ] `:Anki[]`・`:Mark[]` のラベルとリンクのテキストの中では、数字や関数名を囲まずそのまま書いている。`no-inline-code-in-labels`
- [ ] インラインコードの前後に半角スペースを置いていない（`輝度`255`の白` のように地の文と密着させている）。`no-space-around-inline-code`
- [ ] インライン数式の前後には半角スペースを置いている（`画素値 $$i$$ をもつ` のように地の文と離す。約物（`、`・`。`・括弧など）に接する側は入れない）。インラインコードとは逆のルール。`space-around-inline-math`

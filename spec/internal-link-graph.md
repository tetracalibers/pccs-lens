# 記事間内部リンクのネットワークグラフ可視化ツール

## 目的・背景

記事本文（`app/src/routes/**/+page.svx`）どうしは、ルート相対の Markdown リンク（`[接ベクトル](/cg/modeling/bezier-curve-properties/)`）で相互に参照し合っている。しかし記事は「雛形だけ起こしてまだ本文を書いていない」「本文はあるがまだ `draft: true`」という途中段階を長く経るため、**中身のないページへリンクを張ったまま放置される**状態が発生する。

現状（2026-08-22 時点・`main` = `ddcb86b1`）を実測すると、ユニークなリンク先 112 件のうち

- **25 件が本文なし（`## TODO` のみ）のページ** — 読者がクリックしても何も書かれていない
- **18 件が本文はあるが `draft: true`** — 公開ビルドに含まれず、リンクが機能しない

この状態を一望し、**本文が書かれていないページにリンクが張られている箇所から順に潰していく判断材料**を得ることが本ツールの目的である。

現在この情報を得る手段はなく、記事を書くたびに手作業でリンク先の状態を確認するしかない。

## スコープ

### やること

- `app/src/routes/**/+page.svx` を走査し、記事間の内部リンクをネットワークグラフとしてブラウザに描画する
- ノードにページの状態（本文なし / draft / 公開済）を色で表す
- リンク先の状態に応じてエッジを赤・黄でハイライトする
- ユニット単位でノードを囲む（compound node）
- グループ・ユニット・孤立ページのフィルタリング
- ノードのクリックでサイドパネルに詳細（被リンク元・リンク先・記事を開くリンク）を表示
- `.svx` の変更を watch して自動で再スキャン・再描画

### やらないこと

- `app` 本体への機能追加（本ツールは `app` から完全に独立したローカル専用ツール）
- リンクの自動修正・自動生成
- 記事一覧ページ（`/color-theory/` など）やツールページ（`/jis-color-map/`）のグラフ表示
- ノード名での検索・絞り込み
- 「まだ張られていない、張る予定のリンク」（`:::Todo` / `:::Add` 内のリンク）の表示
- CI への組み込み・リンク切れの自動検査

## ユーザーストーリー・主要ユースケース

著者（単独）がローカルで使う開発支援ツールである。

1. **赤を潰す** — ツールを開き、赤いノード（本文なしなのにリンクされている）を見つける。クリックしてサイドパネルで「どの記事から、どんな文脈で張られているか」を確認し、その記事を書く。書き終えたら画面が自動更新され、赤が消えたことを確認する。
2. **黄を確認する** — draft のままリンクされているページを把握し、公開の順序を決める。
3. **クロスリンクを見る** — CG 系の記事を書いているときに、その記事群が色系のどのページに依存しているかを確認する（グループフィルタで色系が OFF でも、リンク先はゴーストとして見える）。
4. **孤立ページを棚卸しする** — 孤立フィルタを ON にして、どこからもリンクされておらず、どこへもリンクしていないページを洗い出す。

## 機能要件

### 走査（スキャン）

#### 対象ページ

`app/src/routes/**/+page.svx` のうち、**次の3グループのいずれかのユニットに属する記事ページのみ**を対象とする。

| グループ | ルート | ユニットの決め方 | ユニット数（ページのあるもの） |
|---|---|---|---|
| 色の理論 | `/color-theory/<slug>/` | `app/src/lib/content-pages/color-theory.yaml` のカテゴリ（`id`） | 9 |
| 色の活用分野 | `/color-fields/<slug>/` | `app/src/lib/content-pages/color-fields.yaml` のカテゴリ（`id`） | 6 |
| CGと画像処理 | `/cg/<unit>/<slug>/` | ルートのパスセグメント（= `app/src/lib/content-pages/cg/<unit>.yaml`） | 10 |

- 色系はルートがフラットなため、所属ユニットは YAML から引く（実測で色系 103 ページすべてが YAML に登録済みであることを確認済み）
- `app/src/routes/concept/+page.svx` は `.svx` だが `layout: concept` で `title` も `group` も持たず、どのユニットにも属さないため**対象外**（リンク元としても数えない）
- CG の YAML は 26 ユニットあるが、実際にページがあるのは 10。**ページが 0 のユニットは囲みごと出さない**（フィルタにも出さない）

#### ページの状態判定

| 状態 | 判定 |
|---|---|
| 本文なし | フロントマター以降が `## TODO` のみ（空白を除いて一致） |
| draft | フロントマターに `draft: true` |
| 公開済 | 上のいずれでもない |

「本文なし」は `## TODO` だけという機械的な線で判定する。「見出しだけ立てて数行」「本文はあるが `:::Todo` が残っている」といった中間状態は**本文ありとして扱う**（閾値による判定は恣意的になるため採らない）。

#### ページタイトル

フロントマターの `title` から取る。`title: ファーガソン曲線 # CG 3-4-3` のように**行末コメントが付いているページがある**ので、`#` 以降は落とす。

#### リンクの抽出

本文中の `[文言](/path/)` 形式のルート相対 Markdown リンクを抽出する。ただし次の範囲は**すべて除外**する。

| 除外範囲 | 理由 |
|---|---|
| `:::Pending` ブロック内 | 採否を検討中の文章であり、まだ本文ではない |
| `:::Add` / `:::Fix` / `:::Delete` ブロック内 | 編集指示メモであり本文ではない |
| `:::Todo` ブロック内 | 図版・デモの未実装プレースホルダであり本文ではない |
| コードブロック（` ``` `）内 | 掲載コードであり本文のリンクではない |

（実測で `:::Pending` 内のリンクが 1 件存在することを確認済み: `app/src/routes/cg/rendering/hidden-surface-removal-methods/+page.svx`）

リンク先が `+page.svelte` として実在する場合（記事一覧ページ、`/jis-color-map/` などのツールページ）は、**意図的なリンクとして扱いグラフから除外する**。

### グラフの描画

#### ノード

対象ページを**すべて**ノードとして出す（リンクに関与していない孤立ページも含む。ただし後述のフィルタでデフォルト非表示）。

塗り色はページの状態で決まり、**リンクされているかどうかは問わない**。

| 状態 | 色 |
|---|---|
| 本文なし | 赤 |
| draft（本文あり） | 黄 |
| 公開済 | 通常色 |

「リンクされている本文なしページ」と「誰からもリンクされていない本文なしページ」の区別は、孤立フィルタで後者を消すことでつける。

#### リンク切れノード

リンク先に `+page.svx` も `+page.svelte` も実在しない場合、**リンク切れ専用のノード**として表示する。所属ユニットが分からないため、**囲みの外にまとめて置く**。

現時点で該当は 0 件だが、記事を書き進めるうえで必ず発生する異常であり、赤（本文なし）よりも強い異常として目立たせる。

#### エッジ

- 有向エッジ（矢印で向きを出す）
- **同一ペアの複数リンクは 1 本に束ねる**（本文中で同じページを何度も参照するケースが多く、実測で 297 リンク / ユニークなリンク先 112）
- **相互リンク（A→B と B→A の両方）は双方向矢印 1 本に潰す**
- エッジの色は**リンク先ノードの状態**で決まる（本文なし = 赤 / draft = 黄 / 公開済 = 通常）。双方向エッジの場合は**両端を見て、より強い警告色を採る**（赤 > 黄 > 通常）

#### 囲み（グループ化）

**ユニット単位**で囲む（Cytoscape.js の compound node）。「CGと画像処理」のような大分類の囲みは設けない。

#### ラベル

- 常時はラベルを出さない（点のみ）
- ホバー / クリックでタイトルを表示する
- ズームレベルに応じてラベルを出し分ける（ズームインしたら表示される）

### フィルタ

**2段構成**とする。

- **上段: 大分類3つのトグル** — 「色の理論」「色の活用分野」「CGと画像処理」。大分類は囲みとしては描かないが、フィルタの単位としては残す
- **下段: ON になっている大分類のユニット個別トグル**
- **孤立ページのトグル** — 入次数・出次数がともに 0 のページの表示 / 非表示

デフォルト状態:

- 「CGと画像処理」のみ ON、色の理論・色の活用分野は OFF
- 孤立ページは非表示

#### クロスグループのゴースト表示

OFF になっている大分類のページであっても、**ON 側のページからリンクが張られている先は「ゴースト」として薄く表示し、囲みの外に置く**。

デフォルト状態（CG のみ ON）で cg → color-theory のリンクが丸ごと消えてしまうと、「CG 系から色系へのリンクを張ることがあるので同じ画面にまとめたい」という本ツールの動機と噛み合わないため。色系 103 ノードで画面を占領されることなく、依存先だけが見える状態にする。

（実測のクロスグループリンク: color-fields → color-theory 13、cg → color-theory 10、color-fields → cg 2）

### サイドパネル

ノードをクリックすると、そのページについて次を表示する。

- タイトル・パス
- 状態（本文なし / draft / 公開済）と所属ユニット
- **被リンク元の一覧**（どの記事から張られているか）
- **リンク先の一覧**
- 記事を開くリンク（`app` の dev サーバー上の該当 URL）

赤いノードを見つけた後に知りたいのは「どの記事から、どんな文脈で必要とされているか」であるため、被リンク元の一覧が中心となる。

### watch と再描画

`.svx` の変更を検知して自動で再スキャン・再描画する。

このとき**既存ノードの座標を保持し、新規・削除されたノードの差分だけを配置し直す**。再スキャンのたびにレイアウトが組み直されて位置が変わると、「さっき見ていた赤がどこへ行ったか」が追えなくなるため。`fcose` は乱数を使うので**シードを固定する**。

## 既存機能との関係・整合

- **`app` 本体には一切手を入れない。** 本ツールは `app/src/routes/**/+page.svx` と `app/src/lib/content-pages/*.yaml` を**読み取るだけ**
- ページの状態判定は `create-cg-page` / `create-color-theory-page` / `create-color-fields-page` スキルが生成する雛形（`## TODO` のみ）と、`publish-article` スキルが外す `draft: true` に依拠する。これらのスキルの規約が変われば本ツールの判定も追随が必要になる
- 除外対象のディレクティブ（`:::Pending` / `:::Add` / `:::Fix` / `:::Delete` / `:::Todo`）は `apply-edit-requests` スキルが扱うものと同一
- `ogimage/` と同じく「ルート直下・独自の `package.json`・`app` の実行環境から独立したツール」という位置づけに揃える

## ドメインルール上の考慮

本ツールは記事のリンク構造のみを扱い、PCCS の色相・トーン、色距離、配色技法といった色彩ドメインのルールには関与しない。グループ名は既存の一覧ページの呼称（「色の理論」「色の活用分野」「CGと画像処理」）に揃える。

## データ・状態

### 入力

| 入力 | 用途 |
|---|---|
| `app/src/routes/**/+page.svx` | 本文・フロントマター（`title` / `draft`）・リンク |
| `app/src/lib/content-pages/color-theory.yaml` | 色の理論のカテゴリ（ユニット）と所属 |
| `app/src/lib/content-pages/color-fields.yaml` | 色の活用分野のカテゴリ（ユニット）と所属 |
| `app/src/lib/content-pages/cg/*.yaml` | CG ユニットの表示名（`title`） |

### 中間データ

スキャン結果をグラフデータ（ノード配列 + エッジ配列）として保持する。ノードは `path` / `title` / `group` / `unit` / `state`、エッジは `source` / `target` / `bidirectional` を持つ。

### 永続化

**しない。** フィルタの設定は localStorage 等に覚えさせず、毎回デフォルト（CG系のみ・孤立非表示）で開く。

### 規模

現時点で 170 ノード / 297 リンク（束ねる前）。ブラウザでの描画に問題のない規模。

## エッジケース・異常系

| ケース | 挙動 |
|---|---|
| リンク先に `+page.svx` も `+page.svelte` も存在しない | リンク切れノードとして囲みの外に表示 |
| リンク先が `+page.svelte`（一覧・ツールページ） | グラフから除外 |
| リンク先が `.svx` だがユニットに属さない（`/concept/`） | グラフから除外 |
| フロントマターの `title` に行末コメントがある | `#` 以降を落としてラベルにする |
| 色系のページが YAML に未登録 | 所属ユニットが解決できない。囲みの外に置き、警告として分かるようにする（現時点で 0 件） |
| CG のユニットにページが 0 件 | 囲みもフィルタも出さない |
| 同一ペアに複数のリンク | 1 本に束ねる |
| 相互リンク | 双方向矢印 1 本、色は両端の強い方 |
| 自己リンク（自分のページへのリンク） | 未検討（現時点で該当なし） |
| `:::Pending` 等の中にしか存在しないリンク | 抽出しない（グラフに現れない） |

## 非機能要件

- **パフォーマンス** — 170 ノード規模。特別な最適化は不要
- **アクセシビリティ** — 著者単独が使うローカル開発ツールのため、要件を置かない
- **モバイル対応** — 不要
- **SEO** — 不要（公開しない）
- **依存の分離** — `link-graph/` の `node_modules` が `app/` と完全に独立していること。`app/package.json` には一切手を入れない

## 制約

- **配置**: ルート直下の `link-graph/`。`ogimage/` と同じく独自の `package.json` を持つ（`proto/` はプロトタイプ置き場なので使わない）
- **実行形態**: Vite の dev サーバー（`npm run dev`）
- **描画ライブラリ**: Cytoscape.js
  - 「ユニット単位の囲み」が本命要件であり、Cytoscape.js は compound node（親ノードが子を囲む枠として描画される）が組み込みで、`fcose` レイアウトが compound を考慮して配置する
  - d3-force はグループの囲みを convex hull で自前描画する必要があり、ノードが動くたびに追随させる手間がかかる。`app` が `d3-shape` / `d3-hierarchy` を持っているが、依存を分ける以上そこに揃える理由はない
- **レイアウト**: `fcose`、シード固定

## 受け入れ条件

- `npm run dev` で開くと、CG系 10 ユニットの囲みとノードが描画される
- 現時点の実データで**赤 25 ノード・黄 18 ノード**が想定どおり色分けされる（うち CG 系の件数は実装時に照合する）
- グループ・ユニット・孤立のフィルタが効き、色系を OFF にしても cg → color-theory の 10 本がゴースト表示で残る
- ノードをクリックするとサイドパネルに被リンク元・リンク先が出て、記事を開けるリンクがある
- `.svx` を編集して保存すると画面が自動で更新され、既存ノードの位置が維持される
- `link-graph/` の `node_modules` が `app/` と完全に独立している

- サイドパネルの「エディタで開く」リンク（`vscode://file/...`）を付けるか — 今回は「記事を開く」リンクのみ
- `:::Todo` / `:::Add` 内のリンクを「張る予定のリンク」として点線で別枠表示する拡張 — 今回はやらない
- ノード名での検索・絞り込み — 今回はやらない
- 画像処理単独（`group: ["ImgP"]` のみ）のページが今後増えたときのグループ扱い
- 自己リンクの扱い（現時点で該当なし）
- `doc.md` / `README.md` の要否と書き方（`ogimage/README.md` に倣うか）

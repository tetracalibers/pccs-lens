案3と案4は同じ挿入位置（すりガラスの段落の直後）に並ぶ。**案3（原理の光線図）が先、案4（結果としての見え）がその直後**という順で置く。

### 背景色は既定のまま

`DEMO_BACKGROUND`（`#26282d`、無彩色）から変えない。この記事は明るさ・光沢が主題で、背景の明度が図の見えを変えるため。

### 色を歪めないための扱い

色彩記事の原則は「色票のような『その色を見せる』対象は `MeshBasicMaterial`、ライトは使わない」。この記事は**特定の色の見えではなく光の向きと明るさが主題**なので、次のように切り分ける。

- **案1・案3・案5（光線図）** — ライトを使わない。すべて `LineBasicMaterial`・`LineDashedMaterial`・`MeshBasicMaterial` で描く
- **案2（見る方向による見え方）** — **ライトを使う。原則の例外。** 陰影とハイライトそのものが主題のため。ただし**物体は無彩色に限り、色相・彩度の見えを読み取らせない**。完了報告に例外である旨を書く
- **案4（すりガラス）** — ライトは使わない。背後の図形は `MeshBasicMaterial` で素の色を出し、ガラスは無色（`color: "#ffffff"`）にする
- トーンマッピングは全案とも既定の `NoToneMapping`（素の `WebGLRenderer` の既定なので何も書かない）

### ラベルの描き方

3次元中の文字は、既存の Three.js デモと同じ **canvas に描いたテクスチャを `Sprite` に貼る方式**（`app/src/lib/demo/threejs/transformation/coordinate-systems/polar-and-cartesian/scene.ts` の `createLabel` が参考実装）。色彩記事のデモはコードが記事に載らないので、この関数は各 `scene.ts` に複製してよい。

### 散らばりは乱数で作らない

案1・案3は「光があらゆる方向へ散らばる」様子を複数本の光線で描く。**方向の生成に `Math.random()` を使わない。** `update()` は操作のたびに走るので、乱数だと散らばり方が毎回変わってチラつく。黄金角スパイラルで単位球面上に決定論的に N 点を取り、**粗さ・拡散の度合いでは開き角だけを変える**。

## 案1：反射光の広がり（正反射と拡散反射を1枚に）

| | |
| --- | --- |
| デモ名 | `reflection-spread` |
| 公開関数 | `createReflectionSpreadScene` |
| コンポーネント | `ReflectionSpreadDemo.svelte` |
| 置き場 | `app/src/lib/demo/threejs/color/reflection-spread/` |

- **見せるもの** — 水平な面に 1 本の入射光が当たり、反射光が跳ね返る。`表面の粗さ` を上げると、面が滑らかな板から凹凸のある面へ変わると同時に、反射光が「入射角＝反射角の 1 本」から「半球状に散らばる多数」へ連続的に変わる
- **操作**
  - `入射角` — `0`〜`80` 度（法線から測る）、初期値 `45`
  - `表面の粗さ` — `0`〜`1`、初期値 `0`（**正反射の状態から始める**。記事が正反射 → 拡散反射の順で説明しているため）
- **挿入位置** — 拡散反射の段落（「表面に細かな凹凸のあるマットな面で起こるのが:Anki[拡散反射]です。〜柔らかく感じられます。」）と、その下の `<!-- ... -->` の暗記メモの**直後**。ここにある `:::Todo` と `<SVGWrapper><DiffuseReflection /></SVGWrapper>` を置き換え、あわせて正反射側の `:::Todo` と `<SVGWrapper><SpecularReflection /></SVGWrapper>` を削除する
- **弱み** — 光線を線で描くだけなら既存 SVG の3D版に近く、3Dの利点は「あらゆる方向＝半球」が見えることに限られる。粗さで光線束を散らすのは幾何光学の模式で、実際の微小面の分布そのものではない

### 実装の決めごと

- **面** — 1 辺 `4` の水平な格子（`LineSegments`、`#8fa3bf`）＋ 半透明の面（`MeshBasicMaterial`、`#8fa3bf`、`opacity 0.12`）。ライトを使わないので、凹凸は**格子線の高さの変化**で読ませる
- **凹凸** — `表面の粗さ` に比例して格子の頂点を上下させる（振幅は `粗さ × 0.06` 程度）。値は決定論的に作る（固定のサイン合成など。乱数を使わない）
- **反射光** — 黄金角スパイラルで単位半球上に `48` 方向を取り、**鏡面反射の向きを軸とする開き角 `粗さ × 90` 度の円錐へ写す**。`粗さ = 0` では全本が鏡面方向に重なり、見た目には 1 本になる（鏡面反射へ自然に収束する）
- **法線** — `#bfbfbf` の破線（`LineDashedMaterial` ＋ `computeLineDistances()`）を反射点から上向きに
- **入射角・反射角の弧** — `EllipseCurve` で描く。**反射角の弧は `粗さ` が小さいときだけ描く**（拡散側では反射角が定まらないため、粗さを上げると弧が消える。これが「正反射では入射角と反射角が等しい／拡散反射では方向が定まらない」の対比になる）。閾値は実装時に決める（`粗さ < 0.05` 程度）
- **ラベル** — 入射光 / 反射光 / 法線 / 入射角 / 反射角。既存 SVG と同じ語を使う
- **カメラ** — `aspectRatio="4 / 3"`、`camera={{ position: [3.2, 2.4, 4.2] }}`、`orbit={{ enableZoom: false, maxPolarAngle: <水平より少し上> }}`（面の下に潜らせない）

### 実装で確定したこと（案3も揃える）

案1の実装時に、上の決めごとから次の点を変えた。**案3は「案1と同じ描き方」で作るため、こちらに揃える。**

- **入射光は`1`本ではなく`3`本にし、面の中央寄りに散らした`3`点でそれぞれ反射させる**（ユーザーの指示による）。入射光はすべて同じ入射角の平行光。反射点ごとに散らばりの位相をずらし、同じ形の光束が並んで見えないようにする。**法線・入射角・反射角は主役の`1`点（原点）にだけ描く**（全点に描くと図が埋まる）。1 点あたりの反射光は`4`本（拡散側で線が増えすぎないようにするため）、光線の長さは`1.25`
- **光束の軸は鏡面反射の向きに固定せず、粗さに応じて法線へ寄せる。** 軸の傾きを `入射角 ×（1 − 粗さ）`、開き角を `粗さ × 85` 度とした。鏡面方向に軸を固定したままだと、開き角が広がったときに光線が面の下（物体の内部）へ潜ってしまう。この式なら粗さ`0`で鏡面反射に一致し、粗さ`1`で法線を軸とした半球（あらゆる方向）になり、途中のどの値でも面の下に出ない
- **開き角の上限は`90`度ではなく`85`度。** `90` にすると面すれすれの光線が格子線と重なって見分けづらくなる
- **入射角の可動範囲は`15`〜`80`度。** `0` 付近では入射光・反射光・法線が重なり、ラベルどうしも重なってしまう
- **反射角の弧は閾値で消さず、粗さ`0`→`0.15`で不透明度を下げて消す。** ステップ 1 目盛りで急に消えるより、拡散側で反射角が読み取れなくなる過程が伝わる
- **入射角・反射角のラベルは、二等分線上に置いたうえで法線から最低 `0.4` だけ左右に引き離す。** 入射角が小さいときに 2 つのラベルが法線上で重なるのを防ぐ
- **ラベルの色は対象の色に揃える**（入射光・入射角はオレンジ、反射光・反射角はイエロー、法線はグレー）。中立色の `#e8e8ee` は使っていない
- **入射角・反射角は弧の線だけでなく、記事の SVG 図解と同じく扇形を塗る**（不透明度`0.32`）。頂点は `EllipseCurve` ではなく同じ三角関数で直接書き換える。`EllipseCurve` だと角度を変えるたびにジオメトリを作り直すことになるため（既存デモの `createSector` と同じ作り）

## 案2：見る方向で変わる見え方（粗さと光沢）

| | |
| --- | --- |
| デモ名 | `surface-gloss` |
| 公開関数 | `createSurfaceGlossScene` |
| コンポーネント | `SurfaceGlossDemo.svelte` |
| 置き場 | `app/src/lib/demo/threejs/color/surface-gloss/` |

- **見せるもの** — 1 つの光源に照らされた無彩色の平らな板。ドラッグで視点を回すと、鏡面寄りでは特定の方向にだけハイライトが現れて眩しく、マット寄りではどこから見ても同じ明るさに見える。中間の値が「拡散反射の中に正反射を一部含む」状態（ツヤのある紙）にあたる
- **操作**
  - `表面の粗さ` — `0.05`〜`1`、初期値 `0.35`（ツヤのある紙寄り＝混在した状態から始める）
  - `光の向き` — `0`〜`80` 度（法線からの傾き）、初期値 `40`
- **挿入位置** — 「実際の物体の表面では、正反射と拡散反射が混在しています。〜ツヤのある紙は、拡散反射の中に正反射を一部含んでいます。」の段落と暗記メモの直後。ここの `:::Todo` を置き換える（記事の「光の反射」節の末尾）
- **弱み** — 見えの計算を Three.js のマテリアル任せにするため、「なぜそう見えるか」の幾何は現れない（案1と対になる）。陰影を使うので色彩記事の原則の例外になる

### 実装の決めごと

- **物体は球ではなく平らな板にする。** 「拡散反射ではどこから見ても同じ強さの明るさ」は平面でこそ成り立つ（球は必ず `N・L` の階調が出て、視点によらず一様には見えない）。記事の例が「ツヤのある紙」であることとも合う
- **板** — `PlaneGeometry(3, 3)` を水平に置き、`MeshStandardMaterial({ color: "#c8c8cc", metalness: 0, roughness })`。**無彩色に限る**
- **ライト** — `DirectionalLight("#ffffff")` ＋ 弱い `AmbientLight("#ffffff")`。強さは実装時に調整
- **光源の位置を示す** — 光源の向きに小さな球（`MeshBasicMaterial`、`#f6ce46`）と入射光の線（`#ef8c00`）を置き、光がどこから来ているかを見えるようにする。`光の向き` を動かすとハイライトが板の上を移動することが読める
- **粗さの下限は `0` にしない。** 環境マップが無いため、`roughness = 0` では板がほぼ真っ黒になり、針の先ほどのハイライトしか出ず読み取れない。下限は `0.05` 程度
- **カメラ** — `aspectRatio="4 / 3"`、`camera={{ position: [2.6, 2.0, 3.2] }}`、`orbit={{ enableZoom: false, maxPolarAngle: <水平より少し上> }}`。**回転が主題なので回転は必ず有効にする**

## 案3：透過光の広がり（正透過と拡散透過を1枚に）

| | |
| --- | --- |
| デモ名 | `transmission-spread` |
| 公開関数 | `createTransmissionSpreadScene` |
| コンポーネント | `TransmissionSpreadDemo.svelte` |
| 置き場 | `app/src/lib/demo/threejs/color/transmission-spread/` |

- **見せるもの** — 板状のガラスに 1 本の光が入り、反対側へ出ていく。`拡散の度合い` を上げると、出ていく光が「直進する 1 本」から「さまざまな方向へ広がる多数」へ変わる。板の中の光路も見える
- **操作**
  - `入射角` — `0`〜`60` 度、初期値 `30`
  - `拡散の度合い` — `0`〜`1`、初期値 `0`（正透過の状態から始める）
- **挿入位置** — すりガラスの段落（「透明なガラスで起こるのが:Anki[正透過]で、〜通り抜けた光の向きがそろっていないためです。」）と暗記メモの直後。ここの `:::Todo` を置き換える
- **弱み** — 光路は入射面という 1 つの平面の中で完結するので 2D の図でほぼ足りる。3D の必然性が案1より薄い

### 実装の決めごと

- **屈折による横ずれは描かない。** 記事は正透過を「入射した光は直進して物体の反対側に出てきます」と書いており、屈折は次節（案5）の主題。**板の中も入射方向のまま直進させる**
- **案1と同じ描き方・同じ色で作る。** 反射と透過を読者が対にして読めるようにするため。決定論的なスパイラルによる散らばり、ラベルの付け方、格子の色は案1に揃える
- **板** — 垂直に立てた薄い直方体。稜線（`EdgesGeometry`、`#e8e8ee`）＋ 半透明の面（`MeshBasicMaterial`、`#24b9ff`、`opacity 0.15`）
- **光線** — 入射光 `#ef8c00`、板の中の光路も入射光と同じ色、出射光 `#f6ce46`。散らばりは**前方半球**の円錐（開き角 `拡散の度合い × 80` 度）に収める
- **カメラ** — `aspectRatio="4 / 3"`、`orbit={{ enableZoom: false }}`

## 案4：すりガラス越しの見え方

| | |
| --- | --- |
| デモ名 | `frosted-glass` |
| 公開関数 | `createFrostedGlassScene` |
| コンポーネント | `FrostedGlassDemo.svelte` |
| 置き場 | `app/src/lib/demo/threejs/color/frosted-glass/` |

- **見せるもの** — 板ガラスの向こうに図形を置き、手前から見る。`ガラスの粗さ` を上げると、向こう側がくっきり → ぼんやりへ変わる。視点を回すと板の厚みと位置関係が分かる
- **操作**
  - `ガラスの粗さ` — `0`〜`1`、初期値 `0`（透明ガラス）
- **挿入位置** — **案3のデモの直後**（同じ「光の透過」節の末尾）。原理の図（案3）→ 結果としての見え（案4）の順
- **弱み** — 「なぜぼやけるか（光の向きが揃わない）」は見えず、結果だけが見える。描画コストが他案より高い

### 実装の決めごと

- **ガラスが図形の一部だけを覆う構図にする。** 板ガラスを図形群の右半分にだけ置き、左半分は素通しで見えるようにする。**同じ図形の「ガラス越し」と「素通し」を同時に見比べられる**ので、ぼけの度合いが読み取りやすい
- **ガラス** — `MeshPhysicalMaterial({ transmission: 1, roughness, thickness: 0.5, ior: 1.5, metalness: 0, color: "#ffffff", transparent: true })`。無色にして、背後の図形の色を変えない
- **背後の図形** — `MeshBasicMaterial`（ライトを受けないので素の色がそのまま出る）。円・四角を数個。細部のぼけを読ませたいので、線の細い形も 1 つ混ぜる
- **ライトは置かない。** transmission は背景を再サンプリングするので、ライトが無くても機能する
- **距離のパラメータは出さない。** 実際のすりガラスは向こう側の物体が離れるほどぼけるが、Three.js の `transmission` のぼけは粗さだけで決まり距離に依存しない。**操作を用意すると誤った挙動を見せることになる**ので、図形とガラスの距離は固定値にする
- **カメラ** — 正面寄りの固定気味の構図。`orbit` は有効にするが、回しすぎるとガラスを真横から見るだけになるので、方位角を `±40` 度程度に制限してよい（実装時に判断）
- 描画コストが高いので `aspectRatio` は控えめに（`16 / 10` 程度）

## 案5：水中の物体が浮いて見える（屈折）

| | |
| --- | --- |
| デモ名 | `apparent-depth` |
| 公開関数 | `createApparentDepthScene` |
| コンポーネント | `ApparentDepthDemo.svelte` |
| 置き場 | `app/src/lib/demo/threejs/color/apparent-depth/` |

- **見せるもの** — 水槽の中の物体から出た光が水面で屈折して観察者の目に届く様子と、その光を目のほうからまっすぐ延長した先＝**見かけの位置**（実際より上）。`観察する角度` と `深さ` を変えると、実際の位置と見かけの位置のずれが変わる
- **操作**
  - `観察する角度` — `0`〜`70` 度（鉛直から測る）、初期値 `45`
  - `深さ` — `0.3`〜`1.5`、初期値 `0.9`
- **挿入位置** — 記事末尾。「水面でストローが折れて見えたり、水槽の中の魚が斜めから見ると実際より上にいるように見えたりするのは、光が屈折しているためです。」の段落と暗記メモの直後。ここの `:::Todo` を置き換える
- **弱み** — 屈折も入射面内で完結するため、光線図としては 2D で足りる。3D の利点は水槽という状況の実感と、見かけの位置が角度で動くことの 2 点

### 実装の決めごと

- **魚は作らない。** 形の作り込みが本題から外れるので、水中の物体は小さな球（`MeshBasicMaterial`、`#ef8c00`）で代用する。ラベルで「実際の位置」と示す
- **屈折はスネルの法則で計算する**（水 `n = 1.33`、空気 `n = 1.0`）
- **光線は 2 本**。物体から観察方向を中心に `±2`〜`3` 度の狭い光束として出し、水面で屈折させる。**屈折後の 2 本を後ろへ延長した交点を見かけの位置とする**（数値的に求める）
- **「見かけの深さ ＝ 実際の深さ ÷ n」は法線に近い方向でだけ成り立つ。** 斜めから見ると見かけの位置は真上ではなく水平方向にもずれる。2 本の延長線の交点を数値で求めればこの振る舞いはそのまま出るので、**「真上にずれる」と読める図にはしない**。記事は「実際より上にいるように見える」としか書いていないので矛盾しない
- **見かけの位置** — `#eb539f` のワイヤーフレーム球（実体でないことを示す）。実際の位置との間を同色の破線で結び、ずれを見せる
- **水** — 半透明（`MeshBasicMaterial`、`#24b9ff`、`opacity 0.15`）。水槽の稜線は `EdgesGeometry`（`#e8e8ee`）
- **目** — 小さな形（球か円錐）＋ ラベル「目」
- **カメラ** — 側面から見る構図が基本。`aspectRatio="4 / 3"`、`orbit={{ enableZoom: false, maxPolarAngle: <水平より少し上> }}`

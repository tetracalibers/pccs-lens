### 軸の取り方（案1・案2・案4に共通）

同次座標 `(x, y, w)` の `w` を 3 本目の軸として立て、**Three.js の座標に `x → x`・`y → y`・`w → z` で対応させる**。

- `w = 1` 平面が画面と平行な板になり、その上の `x` が右・`y` が上という、2次元の図と同じ向きで正規化後の点を読める

## 案1：同次座標の1点は原点を通る1本の直線（実装済み）

- **デモ名** — `homogeneous-line`（`createHomogeneousLineScene` / `HomogeneousLineDemo.svelte`）
- **視点** — 理解
- **見せるもの** — `(x, y, w)` の3次元空間に `w = 1` 平面を描き、同次座標の点と、その定数倍がすべて並ぶ「原点を通る1本の直線」を表示する。直線が `w = 1` 平面と交わる点が正規化後の `(x/w, y/w, 1)` で、`k` をどう動かしても交点は動かない
- **操作** — `x`・`y`・`w`・定数倍 `k`。読み取り専用で `k` 倍した同次座標と正規化した座標を表示する
- **記事に載るコード** — 3軸と `w = 1` 平面（塗り・格子）の生成、同次座標の点、原点を通る直線、`w` で割って交点を求める部分
- **挿入位置** — 「定数倍しても同じ点を表す」の末尾（30行目の TODO コメントの直後）
- **弱み** — 2次元の話に3本目の軸が立つため、`w` を空間的な奥行き（`z`）と読み違えるおそれがある。カメラを回さないと直線と平面の交わりが読み取りにくい

## 案2：射影変換で `w'` が点ごとに変わり、正規化で平面へ戻る（実装済み）

- **デモ名** — `normalization-after-transform`（`createNormalizationAfterTransformScene` / `NormalizationAfterTransformDemo.svelte`）
- **視点** — 理解
- **見せるもの** — `w = 1` 平面上の正方形の4隅に `3×3` 行列を適用すると、`w'` が隅ごとに違うため変換後の点が平面から浮き上がる。正規化のスライダを動かすと、各点が原点を通る直線に沿って `w = 1` 平面へ降り、遠近感のある四辺形になる
- **操作** — 最下行 `p`・`q`、正規化の進み具合 `t`。読み取り専用で `w'` の4隅の範囲（最小 〜 最大）を表示する
- **記事に載るコード** — `Matrix3` の組み立て、4隅への適用、`w'` で割る正規化、`w = 1` 平面と浮いた四角形の線
- **挿入位置** — 「通常の座標への戻し方」の末尾（83行目の TODO コメントの直後）
- **弱み・注意** — 行列の適用と正規化の2段階を1つに詰めるので情報量が多い。`p`・`q` を大きくすると `w'` が `0` に近い隅が飛ぶため、可動範囲を絞る必要がある
- **案1との関係** — 軸の取り方・`w = 1` 平面・正規化の見せ方は案1と揃える（案1を見たあとに読む前提の絵にする）
- **実装時に決めたこと**
  - 行列の上2行は単位行列に固定し、最下行 `(p q 1)` のはたらきだけを見せる。これにより変換後の点は変換前の隅の真上・真下（`x`・`y` が同じで `w` だけ違う位置）に来る
  - 正方形は1辺 `1.2`（半分 `0.6`）、`p`・`q` の可動範囲は各 `-0.5`〜`0.5`。両方を端まで振っても `w'` の最小は `0.4` で、正規化後の4隅は `w = 1` 平面（半分 `2`）に収まる
  - 初期値は `p = 0.4`・`q = 0.15`（4隅の `w'` がすべて異なる状態）・`t = 0`（行列を掛けた直後）
  - 正規化の途中の位置は、縮尺を `1` から `1/w'` へ動かして求める（`1 - t + t/w'`）。原点を通る直線から外れず、案1の「定数倍しても同じ点」とつながる
  - 動く四辺形の色は変換後の色から正規化後の色へ補間する。発着点の四辺形は不透明度 `0.4` で残し、動く四辺形と重なる側（`t` が端）は描かない

## 案3：正方形が四辺形になり、平行線が交わる（実装済み）

- **デモ名** — `parallel-lines-meet`（`createParallelLinesMeetScene` / `ParallelLinesMeetDemo.svelte`）
- **視点** — 理解
- **見せるもの** — `xy` 平面を正面から見て、格子入りの正方形に射影変換をかける。等間隔だった格子が片側へ詰まり、平行だった2辺を延長すると1点で交わる。辺を細かく分割した点をすべて変換することで、直線が直線のまま保たれることも同時に見える
- **操作** — 最下行 `p`・`q`。読み取り専用で延長した2辺の交点の座標を表示する
- **記事に載るコード** — 最下行を含む `Matrix3` の組み立て、格子の全頂点への適用と `w'` 除算、延長線の描画
- **挿入位置** — 「射影変換で保たれる性質」の末尾・`:::Note` の直前（92行目の TODO コメントの直後）
- **弱み・注意** — 案2と数式的には同じ操作なので、両方採ると変換のコードが記事内で重複する。掲載コードは重複を避けて、案3では「格子を分割して全頂点を変換する」側に重心を置く。`p`・`q` が `0` に近いと交点が画面外へ飛ぶ
- **カメラ** — 平面の図なので回転させない（`enableRotate: false`、正面固定）
- **実装時に決めたこと**
  - 3次元の軸・`w = 1` 平面・ラベルは出さない。すべて正規化後の平面の図なので、格子・注目する2辺・交点だけを描く（掲載コードも案1・案2と重複しない）
  - 正方形は1辺 `1.8`（半分 `0.9`）で `6 × 6` の格子。線は1本を `16` 分割し、分割した点をすべて個別に変換する
  - `p` の可動範囲は `0`〜`0.5`（初期値 `0.4`）、`q` は `-0.2`〜`0.2`（初期値 `0.15`）。案2と同じ初期値にして、同じ変換を3次元側と平面側の両方から見られるようにした。両方を端まで振っても `w'` の最小は `0.37` で符号は反転しない
  - **`p` を `0` にできるようにした。** `2` 辺は平行のまま交わらず、アフィン変換では平行性が保たれることをそのまま確かめられる
  - 交点は `1/p` を直書きせず、`x` 方向の無限遠点 `(1, 0, 0)` に行列を掛けて `w'` で割って求める（案4への橋渡しになり、`p = 0` では無限に飛ぶことも式のまま現れる）
  - 交点が図の外（`|x| > 4.5`）まで遠ざかったら点は描かず、Tweakpane 側の表示に「図の外」と添える
  - 延長線は像の直線の向きへ固定長 `5.5` 伸ばし、図の外へ出た分はフレームで切れるに任せる（交点の位置に応じた長さの調整は不要）
  - カメラは `z = 7` の正面固定。交点が右側に出るので、注視点とカメラを `x = 0.5` へ寄せて構図を中央に近づけた

## 案4：無限遠点が消点へ写る

- **デモ名（予定）** — `point-at-infinity`
- **視点** — 理解（発展）
- **見せるもの** — `w = 0` の点は `w = 1` 平面と平行な直線になり交点を持たない（＝無限遠点）。アフィン変換（最下行 `(0 0 1)`）では変換後も平面と交わらないが、射影変換では直線が傾いて平面上の有限の1点＝消点に落ちる。平面上の平行2直線がその点へ向かうことも併せて見せる
- **操作** — 最下行 `p`・`q`、無限遠点の向き
- **記事に載るコード** — `w = 0` の同次座標、行列適用、`w'` が `0` かどうかで交点の有無を分ける処理、平行2直線
- **挿入位置** — 「発展：平行線と無限遠点」の「たとえば、3次元世界の光景を…」段落の直後（消点の `:::Note` の前）
- **弱み・注意** — 案1・案2の見方を理解している前提が要り、単体では読みにくい。`w' → 0` 付近で交点が飛ぶので表示範囲のクリップが必要。消点そのものは別記事（[消点とn点透視図法](/cg/transformation/vanishing-points-and-n-point-perspective/)）の主題と重なるため、この記事では「無限遠点が有限の点に写る」ことに絞る

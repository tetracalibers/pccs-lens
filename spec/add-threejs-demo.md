# CG記事へのThree.jsデモ掲載（add-threejs-demo）

CG記事（`/cg/**`）に、素の Three.js で実装したデモと、そのデモで実際に動いているコードを掲載するスキル。引数で記事 slug を受け取り、記事を解析してデモ案を提案し、合意された案を実装して記事に差し込む。

## 目的・背景

- CG記事に載せるデモの狙いは 2 つある。
  - **内容の理解を助ける** — 静的な図解では伝わりにくい、空間・変換・投影などを操作しながら確かめられるようにする。
  - **実際の応用例を示し、読者の創作への橋渡しとなる** — 記事の理論が実際のコードでどう書かれるかを見せ、読者が自分の制作に持ち帰れるようにする。
- 後者のため、デモとあわせて**そのデモで実際に動いているコード**を記事に掲載する。掲載コードが「一度も実行されていないコード」になることを避けるのが、この仕様全体で最も重視した点。
- 既存の図解は SVG（`svg-diagram-component`）で作られており、静的な図では表現できない題材を扱う手段が無かった。

## スコープ

### やること

- CG記事（`app/src/routes/cg/**/+page.svx`）を対象とした、Three.js デモの実装。
- 記事へのデモの差し込み（import・コンポーネント使用箇所・コードブロック・フロントマターの `visual: true`）。
- デモ案の提案とユーザーによる採否の合意。
- 記事に載らない定型処理を担う共通モジュール（`_shared`）の整備。

### やらないこと

- **記事本文の執筆**。本文は `author-style-writer` の担当で、**このスキルは執筆完了後に呼ばれる**。デモの説明文は書かない。
- 色彩記事（`color-theory`・`color-fields`）への適用。既存の 3D デモ（`PCCSColorSolid3D.svelte`・`MunsellColorSolid3D.svelte`）は Threlte 実装のまま据え置く。
- 「Web」タグの新設。**既存の `図解` タグ（`visual: true`）で代替する**。
- 抜粋コードと `scene.ts` の逐語一致を検証する自動テスト。
- アクセシビリティへの特別な配慮（Tweakpane を素直に使う）。
- 自動で動き続けるアニメーション（操作したときだけ動かす）。

## ユーザーストーリー・主要ユースケース

- 著者が `author-style-writer` でCG記事を書き上げたあと、`/add-threejs-demo <記事slug>` を実行し、提案されたデモ案から載せたいものを選んで実装させる。
- 著者に載せたいデモの構想がある場合は、提案フェーズを飛ばして `/add-threejs-demo <記事slug> <デモの内容>` で直接指定する。
- 読者は記事を読みながらデモを操作して理解を確かめ、直後に掲載されたコードを自分の制作に持ち帰る。

## 機能要件

### 引数

```
/add-threejs-demo <記事slug> [<デモの内容>]
```

- **`<記事slug>`（必須）** — CG記事の slug（例: `basic-transformations`）。`app/src/routes/cg/` を検索して実体を解決する。
  - **0 件・複数ヒットの場合は確認して止める**（`svg-diagram-component` と同じ流儀）。
  - slug が重複する場合のみ、ユニット込みで `transformation/basic-transformations` のように渡す。
- **`<デモの内容>`（省略可）** — 作りたいデモの内容。指定の有無で動作パターンが分かれる。

### 動作パターン

- **パターンA（`<デモの内容>` なし）** — 記事を解析してデモ案を提案し、ユーザーの採否を待ってから実装する。
- **パターンB（`<デモの内容>` あり）** — 提案フェーズを飛ばし、指定された内容のデモを実装する。

### デモ案の提案フォーマット（パターンA）

会話上に表で案を列挙し、番号で採否をもらう。`AskUserQuestion` は選択肢が 2〜4 個に固定されるため、件数が可変なこの用途には使わない。

表の列は次のとおり。

| 列 | 内容 |
| --- | --- |
| `#` | 案番号 |
| 視点 | 理解 / 応用 |
| 何を見せるか | デモで見えるもの |
| 操作 | Tweakpane で操作するパラメータ（操作なしも可） |
| 記事に載る抜粋 | `scene.ts` から抜粋する関数の見込み |
| 挿入位置 | どの節の直後に入れるか |
| この案の弱み | 不採用の理由になりうる限界 |

- **件数は記事次第**。「1 つの視点に 1 デモ」に縛らない。片方の視点が 0 案でもよい。
- 「**この記事に Three.js デモは向かない**」と申告して止まることも許す（例: 知的財産権・CGの歴史）。
- 提示は 5 案程度を上限とする。
- **各案に必ず「弱み」を書く**。AI が自分の案を売り込むだけになるのを防ぐため。
- **挿入位置まで案に含める**ので、採否の合意と同時に挿入位置も合意される。
- ユーザーは番号で `1と3` のように返す（実装順の指定も可）。

### 実装の粒度

- 採用された案を**1 つずつ実装して都度報告**する。複数案が採用されても一度にまとめて実装しない。

### 記事への反映

デモ 1 本ごとに、対象記事へ次を行う。

1. `<script>` ブロックにデモコンポーネントの import を追加する（`CanvasWrapper` が未 import であればあわせて追加）。
2. 合意した挿入位置に `<CanvasWrapper><Demo /></CanvasWrapper>` を差し込む。
3. **その直後に ` ```ts ` のコードブロック**で抜粋コードを置く。**タイトル付き（` ```ts:タイトル `）にはしない** — `lib/remark/code-title.js` が remark 段階で `html` ノードに差し替えるため、後段の shiki のハイライトが効かなくなる。
4. フロントマターに `visual: true` が無ければ追加する。
5. **説明文は書かない。**

### 完了報告

- 挿入した記事と位置
- 作成したファイル
- 抜粋した関数名
- `visual: true` を付与したかどうか
- **このデモで何を操作でき、何が読み取れるか**（記事には書かないが、あとから言及を書き足す材料として報告に添える）
- Tweakpane 初回導入時は `npm install` が必要である旨

## 実装規約

### 実装方式

- **素の Three.js で実装する。Threlte は使わない。**
- パラメータをユーザーが操作するデモでは **Tweakpane** を使う。素の `<input type="range">` による代替は設けない。

### ファイル構成

```
app/src/lib/demo/threejs/
  _shared/                              記事に載らない定型処理
  <ユニット>/<記事slug>/<デモ名>/
    scene.ts                            記事に抜粋する本体。three にのみ依存
    <デモ名>Demo.svelte                 薄い殻（canvas のマウントと Tweakpane 配線）
```

- ディレクトリは**ユニット込み**（`threejs/transformation/basic-transformations/`）。CG記事は今後大量に増えるため、slug の将来的な衝突を避け、記事の在り処と対応が取れるようにする。
- **デモごとにサブディレクトリを作る**。1 デモが 2 ファイル以上になるため、フラットに置くと見通しが悪くなる。
- Svelte コンポーネントは `<デモ名>Demo.svelte`（PascalCase）とする。

### 責務分担

- **`_shared/`（記事に載らない）**
  - renderer の生成（DPR 上限は `min(devicePixelRatio, 2)`）
  - rAF ループ
  - `ResizeObserver` によるリサイズ
  - `dispose`
  - **画面外でのループ停止（必須）**
  - Tweakpane パネルの生成とテーマ変数
  - OrbitControls（抜粋に載らないため共通化する）
  - WebGL 非対応・コンテキストロスト時のメッセージ表示
- **`scene.ts`（記事に抜粋する）**
  - その記事固有のシーン構築・行列計算・ジオメトリ生成・パラメータ適用
  - **`_shared` を import しない。`three` にのみ依存させる**（抜粋がそのまま読者の手元で動く条件）
  - 公開 API は `export const createXxxScene = (ctx) => ({ update?, dispose? })` の 1 関数

### 掲載コードの規約

- **抜粋は逐語コピーに限る。** 記事用に書き下ろしたり、他のAPIから翻訳したりしてはならない。実際に動いている `scene.ts` から切り出す。
- **関数単位で切る。** `// 省略` で中身を削らない。
- 目安は**1 デモにつき 1〜2 関数・合計 40 行程度**。超えるなら `scene.ts` 側を関数分割し、主要な 1 つだけ載せる。`scene.ts` を「抜粋しやすい単位」で設計する責任は実装側に置く。

### 見た目

既存の 3D デモ（`lib/demo/pccs/PCCSColorSolid3D.svelte`）の規約を踏襲する。

- canvas のラッパ: `width: 100%` ＋ `aspect-ratio` ＋ 枠線 ＋ `touch-action: none` ＋ `cursor: grab`
- **`aspect-ratio` はデモごとに変更可**（変換・投影のデモは横長のほうが見やすい場合がある）
- 枠線は `light-dark()` でライト／ダークに追従させる（枠はシーンではなくページ側の要素のため）
- ラッパに `role="img"` ＋ `aria-label`。**Tweakpane パネルはその外（兄弟要素）**に置く
- `{#if browser}` でクライアントのみマウントする

### 背景色

- **ライト／ダーク共通の固定色**とする。`_shared` にニュートラルな暗めグレーの既定を持ち、デモごとに上書き可能にする。
- 理由は 2 つ。
  - 軸ラベルや線の色を、両モードで可読な 1 色に決められる。
  - `scene.ts` にテーマの分岐が入らないため、**抜粋コードの見え方が読者の手元と一致する**。

### Tweakpane

- `devDependencies` に追加する（このリポジトリは `three`・`chroma-js` も `devDependencies` に置いている）。
- ロードは SvelteKit のコード分割任せ（デモを載せた記事のチャンクにだけ入る）。明示的な動的 import はしない。
- CSS 変数（`--tp-base-background-color` など）に `light-dark()` を指定し、**サイトのライト／ダークに追従**させる。
- パネルは **canvas の外（下）** に置く。狭い画面でオーバーレイすると図が隠れ、`touch-action: none` の領域と操作が混ざるため。

### アニメーション

- **自動アニメーションは作らない。** 操作したときだけ動くようにする。

## 既存機能との関係・整合

- **`author-style-writer`** — 本文の執筆はこちらの担当。このスキルは執筆完了後に呼ばれ、本文には手を入れない（デモ・コードブロック・import・フロントマターのみ）。
- **`svg-diagram-component`** — 静的な SVG 図解の担当。引数で図の内容を渡す／プレースホルダを検索する／`visual: true` を付与する、といった流儀を部分的に踏襲するが、**プレースホルダの仕組みは使わない**（CG記事の `:::Todo` は図版用で、デモ用のプレースホルダは存在しない）。挿入位置はデモ案の提案時に合意する。
- **`図解` タグ（`visual: true`）** — `lib/meta/guide-pages.ts` がフロントマターを集約し、`lib/components/m-directive/PageLink.svelte` が一覧リンクにタグを描画する。記事ページ上部（`page-meta`）には `visual` は表示されないため、デモの有無も一覧リンクにのみ現れる。
- **既存の Threlte 3D デモ** — `PCCSColorSolid3D.svelte`・`MunsellColorSolid3D.svelte` はそのまま。今後、色彩記事の 3D デモは Threlte、CG記事の Three.js デモは素の Three.js という 2 系統が並ぶ。
- **`CanvasWrapper`** — 既存の 3D デモ埋め込みと同じく `<CanvasWrapper>` で包む。

## ドメインルール上の考慮

- PCCS の色相・トーンなど色彩ドメインのルールは、このスキルの対象（CG記事）には直接関わらない。
- CG記事は `group: ["CG"]` / `["ImgP"]` を持ち、カリキュラム上の出典区分がタグとして表示される。デモの有無はこの区分とは別軸の情報で、`図解` タグが担う。

## データ・状態

- 永続化するデータは無い。デモのパラメータは Tweakpane が保持する実行時の状態のみで、リロードで初期値に戻る。
- 記事側に増えるのはフロントマターの `visual: true` と、本文中のコンポーネント使用箇所・コードブロック。
- `guide-pages.ts` は `import.meta.glob` でビルド時にフロントマターを集約するため、`visual: true` を書けばタグ表示に反映される。追加の登録作業は不要。

## エッジケース・異常系

- **WebGL 非対応・コンテキストロスト** — メッセージを表示する。メッセージには**どういう環境なら動作するか**を明記する。
- **1 記事に複数デモ** — 複数の rAF ループと WebGL コンテキストが同一ページで同時に走りうるため、**画面外のデモはループを停止する**（`_shared` で必須）。
- **記事slugの解決失敗** — 0 件・複数ヒットは確認して止める。
- **デモに向かない記事** — 提案フェーズで「向かない」と申告して止まってよい。
- **記事が `draft: true` のまま** — 執筆直後に呼ばれる想定のため、下書き記事も対象とする。

## 非機能要件

- **アクセシビリティ** — 特別な配慮は要件としない。既存デモに倣い、ラッパに `role="img"` ＋ `aria-label` を付ける範囲に留める。
- **モバイル** — Tweakpane パネルは canvas の外（下）に置く。OrbitControls を使うため canvas 側は `touch-action: none`。
- **パフォーマンス** — DPR 上限 `min(devicePixelRatio, 2)`、画面外でのループ停止、自動アニメーションなし。
- **バンドル** — SvelteKit のコード分割任せ。`three` は既に色彩記事でも読み込まれている前例がある。

## 制約

- 静的サイト（`adapter-static`）で prerender されるため、Three.js・Tweakpane はクライアントのみで動かす（`{#if browser}` ガード）。
- ` ```lang:タイトル ` 形式のコードブロックは shiki のハイライトが効かない（`code-title.js` が remark 段階で `html` ノードに置き換えるため）。デモのコード掲載ではタイトルを付けない。
- 素の `WebGLRenderer` は既定が `NoToneMapping` のため、Threlte の `<Canvas>` で必要だったトーンマッピングの明示は不要。
- CG記事の実体は `cg/<ユニット>/<記事slug>` で、slug 単体ではパスが確定しない。

## 受け入れ条件

- デモが意図どおり動く。**目視確認はユーザーが行う。**
- `npm run check` が通る。**実行はユーザーが行い、スキルは勝手に実行しない**（`svg-diagram-component` と同じ）。エラー・警告が報告されたら修正する。
- 記事の ` ```ts ` ブロックが `scene.ts` からの逐語抜粋になっている。
- 記事のフロントマターに `visual: true` が付いている。
- 記事本文（地の文）が変更されていない。
- 画面外に出たデモのループが停止する。

## 検討して却下した案

- **Threlte で実装し、本質部分を Three.js に翻訳して掲載** — 記事に載るコードが一度も実行されないコードになる。翻訳が必要になるのはカメラ・投影・ライティングといった**まさにCG記事の主題になりやすい箇所**で、そこに検証の穴が開く。加えて Threlte の `<Canvas>` が既定で行う設定（トーンマッピング等）の差により、デモの見え方と抜粋コードの見え方がずれるという最も気づきにくい乖離が生まれる。抜粋のみ掲載と決めた時点で、定型を `_shared` に追い出せるため素の Three.js を選ぶコストが消えたことも理由。
- **`import src from "./scene.ts?raw"` による自動掲載** — 原理的に乖離ゼロだが、現状の shiki は mdsvex のビルド時ハイライトのため、`?raw` の文字列にはハイライトが効かない。ランタイムハイライタか専用プラグインが必要になる。
- **掲載コードの全文掲載** — renderer 生成からリサイズ・破棄まで含めると 1 デモで 100 行を超え、記事の主題よりボイラープレートが目立つ。
- **「Web」タグの新設** — フロントマターの新フラグ・タグコンポーネント・色トークンが必要になり、CG記事では `図解` `Web` `CG` `画像処理` の 4 タグが並んで狭い画面で折り返す。`図解` タグで代替する。
- **抜粋コードと `scene.ts` の逐語一致を検証する vitest テスト** — 乖離が起きた瞬間に CI で落ちる利点はあるが、過剰。規約の記述に留める。
- **デモ案の提示に `AskUserQuestion` を使う** — 選択肢が 2〜4 個に固定されるため、案の件数が記事ごとに変わるこの用途に合わない。

## 未確定・保留事項

- **軸（`AxesHelper`）・グリッド（`GridHelper`）の共通の見せ方**（色・スケール・ラベル）を規約化するか、デモごとの判断にするか。CG記事は座標系・変換が主題になることが多く、出番は多い見込み。最初の数本で実態が固まってから規約化する想定。
- `_shared` の具体的な API 設計。
- 背景色の具体値。
- Tweakpane の CSS 変数の上書き内容。

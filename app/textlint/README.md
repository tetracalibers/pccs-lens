# 記事本文（`.svx`）の記法・表記チェック

`writing-guides/math-notation-guide.md`（数式・インラインコードの記法）のルールのうち
機械的に判定できるものと、表記揺れの統一を textlint で検査します。

## 使い方

```bash
npm run lint:svx        # 検査する（記法＋表記揺れ）
npm run lint:svx:fix    # 自動修正できるものを直す
```

対象は `src/routes/**/+page.svx`。`.textlintrc.json` で Markdown プラグインの
`extensions` に `.svx` を足しているので、記事ページがそのまま Markdown として検査されます。

検査は2つのパスに分かれていて、個別にも実行できます。**既存記事のベースライン
（`.textlintignore`）が効くのは記法パスだけで、表記揺れは全記事を対象にします**（→「既存記事の扱い」）。

| スクリプト                  | 内容                            | 設定                                              | ベースライン       |
| --------------------------- | ------------------------------- | ------------------------------------------------- | ------------------ |
| `npm run lint:svx:syntax`   | 記法ルール4件（自作）           | `.textlintrc.json` ＋ `--rulesdir textlint/rules` | 効く               |
| `npm run lint:svx:notation` | 表記揺れ（`textlint-rule-prh`） | `.textlintrc.notation.json` ＋ `textlint/prh.yml` | 効かない（全記事） |

## 検査するルール（記法）

| ルール                      | 内容                                                    | 自動修正                          |
| --------------------------- | ------------------------------------------------------- | --------------------------------- |
| `svx-number-in-code`        | 数字は必ずインラインコードにする                        | ○（英字に隣接する数字は報告のみ） |
| `svx-math-function-in-code` | 数学で定義されている関数名もインラインコードにする      | ○（引数が続く形は報告のみ）       |
| `svx-no-space-around-code`  | インラインコードの前後には空白を置かない                | ○                                 |
| `svx-inline-math-spacing`   | インライン数式（`$$...$$`）の前後には半角スペースを置く | ○                                 |

`svx-math-function-in-code` が見るのは、`sin`・`cos`・`log` のように**数学の関数として
定義された名前**だけです（一覧は `rules/svx-math-function-in-code.js` の `FUNCTION_NAMES`）。
`abs`・`min`・`max`・`mod` などプログラミング寄りの名前は、地の文の英単語と衝突しやすいので
対象にしていません。`cosine`・`logo`・`login` のように関数名を含む英単語は、単語境界を見て
いるので検出しません。

ルールの実体は `textlint/rules/`、共通のマスク処理は `textlint/lib/svx.js` にあります。
textlint の Markdown パーサからは mdsvex のディレクティブも KaTeX の数式もただのテキストに
見えるため、検査の対象外にする領域（ディレクティブ・数式・Svelte コンポーネントなど）は
`lib/svx.js` で潰しています。

### 対象外にしているもの

- コードブロック・インラインコード・フロントマター・HTML コメント・`<script>`
- 見出し（`### 2次元直交座標系`、`:WithGroupTag[2次元的な...]` のラベル）
- ディレクティブ名・ラベル・属性（`::Heading2`・`:Anki[10YR]`・`{grades="2,uc"}`）
- Svelte コンポーネントの使用箇所（`<AnalyzedPalette pccs={["v2", "dp4"]} />`）
- リンクの URL・順序付きリストのマーカー
- ブロック数式（段落全体が `$$...$$` のもの）は数式スペースのルールの対象外

### ルールが競合する箇所

インラインコードとインライン数式が隣接する場合、「コードの前後に空白を置かない」と
「数式の前後に半角スペースを置く」が衝突します。既存記事の書き方に合わせて**数式側を優先**し、
``$$\times$$ `1`チャンネル`` のようにスペースを残します。

## 検査するルール（表記揺れ）

表記揺れは `textlint/prh.yml`（`textlint-rule-prh` の辞書）で統一します。現在の項目は次のとおりで、
いずれも自動修正できます。

| 直す前                     | 直した後               | 補足                                                     |
| -------------------------- | ---------------------- | -------------------------------------------------------- |
| もともと                   | 元々                   |                                                          |
| 〜しているぶん、〜そのぶん | 〜している分、〜その分 | 形式名詞の「ぶん」を漢字にする                           |
| 桿体                       | 杆体                   |                                                          |
| あいだ                     | 間                     |                                                          |
| ほか                       | 他                     | 「〜にほかなりません」のように「な」が続く形は対象外     |
| そろう・そろえる           | 揃う・揃える           | 活用語尾（わ・い・う・え・お・っ）までまとめて漢字にする |
| この時                     | このとき               | 「この時代」「この時点」のように別語になる形は対象外     |
| 例えば                     | たとえば               |                                                          |

- **項目を増やすときは `prh.yml` に追記します。** `expected`（直した後）と `pattern`（直す前。
  `/.../` で書くと正規表現）の組で、`$1` などの後方参照も使えます。
- **`specs` は辞書の自己テスト**で、textlint の起動時に検証されます（期待と違えばエラーで止まる）。
  置き換わってほしい例と、**置き換わってほしくない例**（`from` と `to` を同じにする）を書いておくと、
  パターンを広げたときの取りこぼし・行きすぎに気づけます。
- 形式名詞の「ぶん」は、直前が `の`・`な` や動詞・形容詞の活用語尾のときだけ置き換えます。
  「たぶん（多分）」「じゅうぶん（十分）」「ぶぶん（部分）」や、`半分ぶん` のように直前が「分」の
  形は対象外です（`半分分` になってしまうため）。
- 「ほか」は、直後が `な` のときは置き換えません（`〜にほかなりません`・`〜するほかない` を
  `他` にすると不自然になるため）。
- 「そろう」「そろえる」は、活用語尾（`わ`・`い`・`う`・`え`・`お`・`っ`）までを1項目でまとめて
  漢字にします。直前が `そろ` のときは置き換えません（`そろそろいい` のように「そろそろ」＋活用
  語尾と同じ並びを拾ってしまうため）。
- 「この時」は、`代`・`期`・`点`・`間`・`刻`・`計`・`系` が続かないときだけ「このとき」にします
  （`この時代`・`この時点`・`この時系列` などは別語のため）。
- 表記揺れの検査でも、**コードブロック・インラインコードは対象外**です（デモの掲載コードの
  コメントは検査されません）。地の文・見出し・`:Anki[]` の中身は検査されます。

## 既存記事の扱い

記法ルールは**新しく書く記事から適用**する方針です。ルール導入時点で違反を含んでいた記事は
`.textlintignore` に列挙して対象外にしています（違反のなかった既存記事は対象のままなので、
あとから違反が入ると検出されます）。

既存記事の記法を直したら、その記事の行を `.textlintignore` から削除してください。
新しく作る記事は `.textlintignore` に追記せず、検査対象のままにします。

**表記揺れ（`lint:svx:notation`）はベースラインの対象外で、常に全記事を検査します。** 記事全体で
表記が揃っていることに意味があり、直す手間も1語ずつの置き換えで済むためです。

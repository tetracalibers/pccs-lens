# 記事本文（`.svx`）の記法・表記チェック

`writing-guides/math-notation-guide.md`（数式・インラインコードの記法）のルールのうち
機械的に判定できるものと、表記揺れの統一を textlint で検査します。

## 使い方

```bash
npm run lint:svx            # 検査する（記法＋表記揺れ）
npm run lint:svx:fix        # 自動修正できるものを、変化が無くなるまで繰り返し直す
npm run lint:svx:advisory   # 判断が要る指摘を見る（非ブロッキング）
```

対象は `src/routes/**/+page.svx`。`.textlintrc.json` で Markdown プラグインの
`extensions` に `.svx` を足しているので、記事ページがそのまま Markdown として検査されます。

検査は3つのパスに分かれていて、個別にも実行できます。

| スクリプト | 内容 | 性質 | ベースライン |
| --- | --- | --- | --- |
| `npm run lint:svx:syntax` | 記法ルール（自作・12件） | **ブロッキング**（公開時ゲートが見る） | 効く |
| `npm run lint:svx:advisory` | 判断が要る指摘（自作・5件） | 非ブロッキング | 効かない（全記事） |
| `npm run lint:svx:notation` | 表記揺れ（`textlint-rule-prh`） | 非ブロッキング | 効かない（全記事） |

**組織原則: 自動修正できない指摘は `syntax` パスに置かない。** 囲む範囲の判断が要るもの・
文章を書き直す必要があるものは、すべて `advisory` パスに置きます。この原則があるから、
公開時ゲート（`publish-article` 手順0）から `--fix` を自動実行しても安全になります
（収束させれば必ず0件になり、決定的な変換しか起きない）。

ルールの実体は `rules/`（syntax）と `rules-advisory/`（advisory）、共通のマスク処理と
スコープ解析は `lib/` にあります。**ディレクトリでパスを分けているのは、`--rulesdir` で
読み込んだルールが全部有効になるため**で、パスごとに有効なルールを設定で切り替えることは
できません。

### `--fix` は1パスでは収束しない

ルールの自動修正が別のルールの違反を新たに生みます。たとえば `輝度 255 の白` は、
数字ルールが `` 輝度 `255` の白 `` にした結果、インラインコードの前後にスペースが生まれて
`svx-no-space-around-code` の違反が4件**新たに発生**し、2パス目で `` 輝度`255`の白 `` に
収束します（実測: 全記事で 665件 → 24件 → 21件）。

`npm run lint:svx:fix` は `scripts/lint-svx-fix.mjs` で、**中身が変わらなくなり、かつ
自動修正できる指摘が残っていない**ところまで繰り返します。

```bash
npm run lint:svx:fix                                            # 全記事（ベースラインが効く）
npm run lint:svx:fix -- src/routes/cg/basics/anti-aliasing/+page.svx
npm run lint:svx:fix -- --no-baseline src/routes/cg             # ベースラインを無効にする
npm run lint:svx:fix -- --syntax-only --max-passes 8            # 表記揺れを当てない
```

## 検査するルール（記法・`syntax` パス）

すべて `--fix` で直ります。

| ルール | 内容 |
| --- | --- |
| `svx-number-in-code` | 数字は必ずインラインコードにする（小数はまとめて1つの数値。単位つきは単位ごと囲む） |
| `svx-math-function-in-code` | 数学で定義されている関数名もインラインコードにする |
| `svx-no-space-around-code` | インラインコードの前後には空白を置かない |
| `svx-inline-math-spacing` | インライン数式（`$$...$$`）の前後には半角スペースを置く |
| `svx-inline-math-dfrac` | インライン数式の中の `\frac` を `\dfrac` にする |
| `svx-math-prime` | 数式の中のアポストロフィ `'` を `^{\prime}` にする |
| `svx-block-math-linebreak` | ブロック数式の改行を `\\\\`（4つ）に、`\frac` を含むブロックの行末を `\\\\\\\\`（8つ）にする |
| `svx-no-code-in-label` | `:Anki[]`・`:Mark[]` のラベルとリンクのテキストからインラインコードを外す |
| `svx-action-no-inline-math` | `:::Action` のインライン数式を、Unicode で書ける範囲でインラインコードにする |
| `svx-block-math-symbol-unify` | ブロック数式を説明する文では、その式の記号をインライン数式で書く |
| `svx-sentence-math-unify` | インライン数式を含む文では、数式・変数・関数名をインライン数式に統一する |
| `svx-article-symbol-unify` | 同じ対象を表す記号は記事全体でどちらか一方（数式側）に統一する |

`svx-math-function-in-code` が見るのは、`sin`・`cos`・`log` のように**数学の関数として
定義された名前**だけです（一覧は `lib/math-tokens.js` の `FUNCTION_NAMES`）。
`abs`・`min`・`max`・`mod` などプログラミング寄りの名前は、地の文の英単語と衝突しやすいので
対象にしていません。`cosine`・`logo`・`login` のように関数名を含む英単語は、単語境界を見て
いるので検出しません。

### 単位辞書

`svx-number-in-code` は `lib/math-tokens.js` の `UNITS` を見て、単位つきの数値を単位ごと
囲みます（`600nm` → `` `600nm` ``）。ガイドが「単位つきの数値は、単位も含めてインラインコードに
します」と明記しているので判断の余地がありません。

**単位以外は辞書に載せません。** 色記号（PCCS トーン `v2`・マンセル `5R`）・固有名詞
（`3D`・`3DCG`・`3DS`）・BC 記法（`BC2万年`）はトークンの列挙で例外化せず、advisory パスで
判断待ちとして出します。**1文字の単位も、記事で実際に使うもの（`K`）だけ**にしています
（`m`・`s`・`A`・`W` を入れると、`2s`（`s` 倍）・`2A`（点 A）のような変数との積を
単位つきの数値と誤認します）。

### スコープ解析の3ルール（適用順序が意味を持つ）

`svx-block-math-symbol-unify`・`svx-sentence-math-unify`・`svx-article-symbol-unify` は、
1つのトークンだけを見ても判定できません。共通の解析は `lib/math-scope.js` にあり、
**スコープの狭い順**（同じ文 → ブロック数式のある節 → 記事全体）に根拠を確定させます。
1つのトークンに根拠は1つしか付かないので、3つのルールが同じ箇所を二重に報告することは
ありません。

- **昇格（インラインコード → インライン数式）だけを自動修正します。** 3つとも「数式側へ
  揃える」向きが一意に決まります。
- **降格（インライン数式 → インラインコード）は自動修正しません。** 降格の根拠は「3つに
  拾われなかったこと」なので、スコープ検出の取りこぼしがそのまま誤修正になります。
  素朴に「KaTeX 必須記号を含まない `$$…$$`」で数えると、全記事857件中478件が候補に挙がり、
  その大半はブロック数式の記号を説明している `$$t$$`・`$$C(t)$$`（維持が正しいもの）です。
  降格候補は advisory パスの `svx-prefer-inline-code` が**残差として**報告します。
- **`:::Action` のテキストは3つとも対象外**（ガイドの明示）。**数字も対象外**です。数字の
  判定は広く取る必要があり（負号・小数・タプル・範囲・単位つき）、狭く取ると `` `-1` ``・
  `` `(1, 0, 0)` `` を変数と誤認します。
- **語を式と見誤らないことを優先しています。** 英字の並びが3文字以上あるもの（`RGB`・
  `sRGB`）は、関数名でなければ式と見なしません。ここを緩めると `` `RGB` `` を `$$RGB$$` に
  昇格させてしまいます。

## 検査するルール（`advisory` パス）

**どれも自動修正しません。** 判断は `/format-math-notation` が引き受けます。

| ルール | 内容 |
| --- | --- |
| `svx-code-range-number` | 単位辞書で解決できない英字に隣接した数字（`3DCG`・`v5`・`BC2万年`）。囲む範囲の判断 |
| `svx-code-range-function` | 引数が続く関数名（`sin(x)`）。囲む範囲の判断 |
| `svx-math-unify-manual` | 昇格の対象だが組み直しに判断が要るもの（`` `a = dy / dx` `` → `\dfrac`） |
| `svx-action-math-rewrite` | `:::Action` の、Unicode では書けない式。日本語への言い換えが要る |
| `svx-prefer-inline-code` | 降格候補（3つの統一ルールに拾われなかった `$$…$$`） |

### 対象外にしているもの

- コードブロック・インラインコード・フロントマター・HTML コメント・`<script>`
- 見出し（`### 2次元直交座標系`、`:WithGroupTag[2次元的な...]` のラベル）
- ディレクティブ名・ラベル・属性（`::Heading2`・`:Anki[10YR]`・`:Mark[2次曲線]`・`{grades="2,uc"}`）
- Svelte コンポーネントの使用箇所（`<AnalyzedPalette pccs={["v2", "dp4"]} />`）
- リンク（`[2次曲線](/cg/modeling/quadratic-curve/)`）。数字ルール・関数名ルールでは**テキストごと**対象外にしています（リンクのラベルではインラインコードを使わない規約のため。→ `writing-guides/math-notation-guide.md`）。数式スペースのルールは URL だけを対象外にします
- 順序付きリストのマーカー
- ブロック数式（段落全体が `$$...$$` のもの）は数式スペースのルールの対象外
- `:::Action` のテキストは、スコープ解析の3ルールの対象外（`svx-action-no-inline-math` だけが見ます）

### ルールが競合する箇所

インラインコードとインライン数式が隣接する場合、「コードの前後に空白を置かない」と
「数式の前後に半角スペースを置く」が衝突します。既存記事の書き方に合わせて**数式側を優先**し、
``$$\times$$ `1`チャンネル`` のようにスペースを残します。

## 検査するルール（表記揺れ）

表記揺れは `textlint/prh.yml`（`textlint-rule-prh` の辞書）で統一します。現在の項目は次のとおりで、
いずれも自動修正できます。

| 直す前                     | 直した後               | 補足                                                        |
| -------------------------- | ---------------------- | ----------------------------------------------------------- |
| もともと                   | 元々                   |                                                             |
| 〜しているぶん、〜そのぶん | 〜している分、〜その分 | 形式名詞の「ぶん」を漢字にする                              |
| 桿体                       | 杆体                   |                                                             |
| あいだ                     | 間                     |                                                             |
| ほか                       | 他                     | 「〜にほかなりません」のように「な」が続く形は対象外        |
| そろう・そろえる           | 揃う・揃える           | 活用語尾（わ・い・う・え・お・っ）までまとめて漢字にする    |
| つなぐ・つながる           | 繋ぐ・繋がる           | 活用語尾（が・ぎ・ぐ・げ・ご・い）までまとめて漢字にする    |
| ふるまい                   | 振る舞い               | 名詞の形だけが対象（`ふるまう` などの活用形は入れていない） |
| あとに・あとから・あとで   | 後に・後から・後で     | 続く助詞までまとめて漢字にする（「足あと」「傷あと」は対象外）|
| たりない                   | 足りない               | 「〜あたりないし」「隔たりないし」のような形は対象外        |
| ふつう                     | 普通                   |                                                             |
| あわせる                   | 合わせる               | 活用語尾（る・て・た・な・ら・れ・よ）までまとめて漢字にする |
| ほうが                     | 方が                   |                                                             |
| ころ                       | 頃                     | 時期を表す「ころ」。`ところ`・`出どころ`・`こころ` は対象外  |
| なめらか                   | 滑らか                 |                                                             |
| とおり                     | 通り                   |                                                             |
| いちばん                   | 一番                   |                                                             |
| もたせる                   | 持たせる               | 「たもたせる」（保たせる）は対象外                          |
| もちます                   | 持ちます               | 「たもちます」（保ちます）は対象外                          |
| たびに                     | 度に                   |                                                             |
| つねに                     | 常に                   | 「きつねに」（狐に）は対象外                                |
| よびます                   | 呼びます               | 「およびます」（及びます）は対象外                          |
| ふくらむ                   | 膨らむ                 | 活用語尾（む・み・ん・ま）までまとめて漢字にする（「ふくらはぎ」は対象外）|
| 時間がたつ                 | 時間が経つ             | 「時間が」に続く形だけが対象。活用語尾（つ・ち・っ）までまとめて漢字にする|
| うえで                     | 上で                   |                                                             |
| なかで                     | 中で                   | 「おなかで」「せなかで」「まんなかで」のような形は対象外    |
| こまやか                   | 細やか                 |                                                             |
| うかべ                     | 浮かべ                 | 「思いうかべる」→「思い浮かべる」                            |
| そのつど                   | その都度               | 「その集い」（そのつどい）は対象外                          |
| そって                     | 沿って                 | 直前が「に」のときだけ（「にそって」→「に沿って」）        |
| この時                     | このとき               | 「この時代」「この時点」のように別語になる形は対象外        |
| 例えば                     | たとえば               |                                                             |
| 掛ける・掛かる             | かける・かかる         | 活用語尾と複合名詞（掛け算・掛け合わせる）までまとめてかなにする |
| 凹み                       | へこみ                 | 名詞の形だけが対象（`凹凸`・`凹形状`・`凹んで` は入れていない） |
| 言います                   | いいます               |                                                             |
| 既に                       | すでに                 |                                                             |

- **項目を増やすときは `prh.yml` に追記します。** `expected`（直した後）と `pattern`（直す前。
  `/.../` で書くと正規表現）の組で、`$1` などの後方参照も使えます。
- **`specs` は辞書の自己テスト**で、textlint の起動時に検証されます（期待と違えばエラーで止まる）。
  置き換わってほしい例と、**置き換わってほしくない例**（`from` と `to` を同じにする）を書いておくと、
  パターンを広げたときの取りこぼし・行きすぎに気づけます。
- 形式名詞の「ぶん」は、直前が `の`・`な` や動詞・形容詞の活用語尾のときだけ置き換えます。
  「たぶん（多分）」「じゅうぶん（十分）」「ぶぶん（部分）」や、`半分ぶん` のように直前が「分」の
  形は対象外です（`半分分` になってしまうため）。
- 「ほか」は、直後が `な` のときは置き換えません（`〜にほかなりません`・`〜するほかない` を
  `他` にすると不自然になるため）。
- 「そろう」「そろえる」は、活用語尾（`わ`・`い`・`う`・`え`・`お`・`っ`）までを1項目でまとめて
  漢字にします。直前が `そろ` のときは置き換えません（`そろそろいい` のように「そろそろ」＋活用
  語尾と同じ並びを拾ってしまうため）。
- 「つなぐ」も、活用語尾（`が`・`ぎ`・`ぐ`・`げ`・`ご`・`い`）までを1項目でまとめて漢字にします
  （`繋がる`・`繋ぎ目`・`繋いで`）。直前が `せ` のときは置き換えません（`せつない`（切ない）が
  `せ繋い` になってしまうため）。
- 「ふるまい」は名詞の形だけを対象にしています（`ふるまう`・`ふるまって` のような活用形は辞書に
  入れていません）。
- 「あと」は、続く助詞（`に`・`から`・`で`）までを1項目でまとめて漢字にします（`後に`・`後から`・
  `後で`）。直前が `足`・`傷` のときは置き換えません（`足あと`・`傷あと` の「あと」は〈跡〉の意味で、
  `足後に` になってしまうため）。`あとの`・`あとは` は助詞の選択肢に入れていないので、かなのまま
  残ります（対象を広げるときは選択肢を足します）。
- 「たりない」は、直前が `あ`・`当`・`隔`・`っ` のときは置き換えません（`〜あたりないし`・
  `隔たりないし`・`ぴったりない` を拾ってしまうため）。`少したりない` を拾えるよう、`し` は
  除外していません。
- 「この時」は、`代`・`期`・`点`・`間`・`刻`・`計`・`系` が続かないときだけ「このとき」にします
  （`この時代`・`この時点`・`この時系列` などは別語のため）。
- 「あわせる」は、活用語尾（`る`・`て`・`た`・`な`・`ら`・`れ`・`よ`）までを1項目でまとめて漢字に
  します（`合わせる`・`合わせて`・`合わせた`）。`あわせ` に続けて別語になる形は成立しないため、
  絞り込みはしていません。
- 「掛ける」「掛かる」は、活用語尾に加えて複合名詞まで含めてかなにします（`かけ算`・
  `かけ合わせる`・`かかって`）。直前が `仕`・`手`・`気`・`足` のときは置き換えません
  （`仕掛け`・`手がかり`・`気がかり`・`足がかり` が `仕かけ`・`手かかり` になってしまうため）。
- 時期を表す「ころ」は、直前が `と`・`ど`・`こ` のときは置き換えません（`ところ`・`出どころ`・
  `ところどころ`・`こころ` を拾ってしまうため）。直後が `が`・`げ`・`ぶ`・`も`・`す`・`し`・`っ`・
  `こ`・`り` のときも対象外です（`ころがる`・`ころげる`・`ころぶ`・`ころも`・`ころす`・`ころころ`・
  `ころっと`・`ころり` になってしまうため）。現在の記事にある「ころ」はすべて `ところ`・`出どころ` で、
  この絞り込みですべて除外されます。
- 「凹み」は名詞の形だけを対象にしています（`凹凸`・`凹形状`・`凹んで` は辞書に入れていません）。
- 「もたせる」「もちます」は、直前が `た` のときは置き換えません（`たもたせる`（保たせる）・
  `たもちます`（保ちます）が `た持たせる`・`た持ちます` になってしまうため）。指定されたこの2つの形だけを
  対象にしていて、`もつ`・`もった` のような他の活用形は辞書に入れていません。
- 「つねに」は、直前が `き` のときは置き換えません（`きつねに`（狐に）を拾ってしまうため）。
- 「よびます」は、直前が `お` のときは置き換えません（`およびます`（及びます）が `お呼びます` に
  なってしまうため）。
- 「ふくらむ」は、活用語尾（`む`・`み`・`ん`・`ま`）までを1項目でまとめて漢字にします
  （`膨らむ`・`膨らみ`・`膨らんで`・`膨らませる`）。`ふくらはぎ` は `は` が続くので、活用語尾の
  文字クラスに入れていません（対象を広げるときも `は` は足しません）。
- 時間の経過を表す「たつ」は、`時間が` に続く形だけを対象にしています（`たつ` 単独では
  〈立つ〉〈建つ〉と衝突するため）。活用語尾（`つ`・`ち`・`っ`）までを1項目でまとめて漢字に
  します（`時間が経つ`・`時間が経ち`・`時間が経って`）。`時が経つ`・`年月がたつ` のような
  他の主語の形は辞書に入れていません。
- 「うかべ」は、その並びで別語になる形が記事に無いため絞り込んでいません（「〜だろう**か**」＋
  「**べ**つに」が続けば別語になりますが、記事にその並びは無く、「べつ」も常に「別」と漢字で
  書いているためです）。
- 「そのつど」は、直後が `い` のときは置き換えません（`そのつどい`（その集い）が `その都度い` に
  なってしまうため）。`その都度いったん` のような形は取りこぼしますが、本文を壊すより取りこぼす
  側に倒しています。
- 「そって」は、直前が `に` のときだけ置き換えます（`にそって` → `に沿って`）。〈そ〉で終わる語に
  `って` が続く形（`へそって`・`うそって`・`だからこそって`）や、〈反って〉〈剃って〉を拾わない
  ようにするためです。
- 「なかで」は、直前が `お`・`せ`・`さ`・`か`・`だ`・`ん` のときは置き換えません
  （`おなかで`・`せなかで`（背中）・`さなかで`（最中）・`なかなかで`・`ただなかで`・
  `まんなかで`（真ん中）を拾ってしまうため）。`なかでも` は `中でも` になります。
- 「いちばん」「たびに」「言います」「既に」は、その並びで別語になる形が無いため絞り込んでいません
  （`たびに` は、`ふたたび` に `に` が続く形が成立せず、〈旅〉〈足袋〉をかなで書くことも無いため
  リテラルのままです）。
- 「ほうが」「なめらか」「とおり」「うえで」「こまやか」は、その並びで別語になる形が無いため
  絞り込んでいません
  （`ほうがいい`→`方がいい`、`なめらかさ`→`滑らかさ`、`とおり抜ける`→`通り抜ける` も同じ向きです）。
- 表記揺れの検査でも、**コードブロック・インラインコードは対象外**です（デモの掲載コードの
  コメントは検査されません）。地の文・見出し・`:Anki[]` の中身は検査されます。

## 既存記事の扱い

記法ルールは**新しく書く記事から適用**する方針でした。ルール導入時点で違反を含んでいた記事は
`.textlintignore` に列挙して対象外にしています（違反のなかった既存記事は対象のままなので、
あとから違反が入ると検出されます）。

**CG記事（`src/routes/cg/**`）はベースラインを解消済みで、1件も載っていません。** 記法の
強制化はCG記事を対象にしていて、残っているのは色の理論・色の活用分野の記事です。
なお `writing-guides/NOTATION-TASKLIST.md` の `[x]` はこのベースラインとは別の記録で、
「`format-math-notation` を実行して advisory の指摘まで判断し終えた」ことを表します。

既存記事の記法を直したら、その記事の行を `.textlintignore` から削除してください。
新しく作る記事は `.textlintignore` に追記せず、検査対象のままにします。

数式・インラインコードの記法（`writing-guides/math-notation-guide.md`）については、
`/format-math-notation <slug>` が advisory の判断とベースラインの解除を行います
（自動修正できる分は `npm run lint:svx:fix` の収束ループが片付けます）。

**表記揺れ（`lint:svx:notation`）と advisory パスはベースラインの対象外で、常に全記事を
検査します。** 表記揺れは記事全体で表記が揃っていることに意味があり、advisory は
ブロックしないので、ベースラインで隠す理由がありません。

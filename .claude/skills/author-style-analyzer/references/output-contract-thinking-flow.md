# Output Contract: thinking-flow

`writing-guides/thinking-flow.md` と `writing-guides/evidence/thinking-flow/` に固有の規約。共通規約は [`output-contract.md`](./output-contract.md) を参照する。**統合の担当観点が thinking-flow のときだけ読む。**

## 扱う対象

著者が文章を書く際に行っていると考えられる判断を扱う。

主な対象：

- 執筆時の問題認識
- 説明方法を選択する判断
- 読者の理解状態に関する想定
- 抽象と具体を切り替える条件
- 説明を補足、省略、展開する条件
- 次の話題へ進む判断
- 推敲時の判断

記事の見出し順や段落構成そのものは、主な対象にしない。

## 追加できる項目

共通の基本形式に加えて、次を使ってよい。

```markdown
- 認識する問題：
- 選択する説明戦略：
- 読者に起こそうとする理解の変化：
- 次の判断へ進む条件：
```

意味のある情報がない項目は省略する。

## 必須要素

最低限、次を含める。

- ガイドの目的
- 執筆前の判断
- 説明を進める基本的な思考の流れ
- 読者の疑問を扱う判断
- 抽象と具体を切り替える判断
- 説明を深める、または省略する判断
- 話題を展開する判断
- 推敲時の判断
- 再現可能な条件付きルール
- 適用上の注意
- 一般化できない判断

思考フローは、見出し順の言い換えではなく、問題認識と判断の連鎖として記述する。

## 根拠の書き方

`evidence/thinking-flow/<slug>.md` の支持行には、本文中の該当箇所を短く添える。

```markdown
- TF-020（冒頭で直前記事の未着手部分を呼び戻し、今まさに生じる問いを立てる）
```

この観点は完成記事の本文からの推測を扱うため、根拠は「本文にそう書かれている」ことしか示せない。判断の意図は本文から切り分けられないため、確度の上限に次を反映する（詳細は `evidence/thinking-flow/_README.md`）。

- 対比・具体例の先出し・抽象→具体の翻訳など、一般的な説明技法と重なる判断は確度を条件付き以下に抑える
- テーマ主導の面がある判断は、テーマ必然を超える部分だけを根拠に数える
- 共有コンポーネント・記法規約に依存する観察は確度を抑える

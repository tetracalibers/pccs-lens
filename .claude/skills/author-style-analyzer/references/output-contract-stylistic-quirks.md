# Output Contract: stylistic-quirks

`writing-guides/stylistic-quirks.md` と `writing-guides/evidence/stylistic-quirks/` に固有の規約。共通規約は [`output-contract.md`](./output-contract.md) を参照する。**統合の担当観点が stylistic-quirks のときだけ読む。**

## 扱う対象

文やフレーズのレベルで観察できる表現上の癖を扱う。

主な対象：

- 頻出する言い回し
- 文末表現
- 接続表現
- 語彙の選択
- 断定や推測の調整
- 記号や表記
- 読者との距離感
- あまり使用しない表現

文章全体の構成やGit差分は、主な対象にしない。

## 追加できる項目

共通の基本形式に加えて、次を使ってよい。

```markdown
- 表現：
- 使用目的：
- 使用されやすい文脈：
- 近いが著者らしくない表現：
- 過剰使用への注意：
```

`使用目的` / `使用されやすい文脈` は、`ルール` 欄・適用条件欄の言い換えになるなら書かない。

## 必須要素

最低限、次を含める。

- ガイドの目的
- 全体的な語り口
- 導入表現
- 説明を展開する表現
- 話題をつなぐ表現
- 例示表現
- 対比、否定、限定の表現
- 推測と断定の調整
- 文末表現
- 表記上の癖
- あまり使わない表現
- 再現時の注意

頻出表現の一覧だけで終えず、使用文脈と目的を記述する。

## 根拠の書き方

`evidence/stylistic-quirks/<slug>.md` の支持行には、本文中の該当箇所を短く添える。

```markdown
- SQ-032（「このように、高い解像度で細かく色を求めてから平均することで…」）
```

**この観点はルール名の短縮形が最も多く使われていた。** 本体の見出しは補足句を伴う長い名前（`ヘッジ文末：主観・一般則を和らげる`）だが、根拠側では `ヘッジ文末` と書かれ、機械照合すると支持0件と出るルールが76件中22件生じていた。ID で参照する規約は、この破綻を塞ぐためのものである。**ルール名を書かず、ID だけを書く。**

多くの語形は日本語の技術文書一般に共通するため、確度の上限に次を反映する（詳細は `evidence/stylistic-quirks/_README.md`）。

- 著者固有性は語そのものではなく、何に当てるか・何に当てないかという配分に置く
- です・ます調、括弧注記、「〜と呼ばれる」などの汎用の語形は、出現数では確度を上げない
- `:Anki`・`:::Action`・TermCard などサイト共通の仕組みに依存する観察は確度を抑える

# Output Contract: refine-style

`writing-guides/refine-style.md` と `writing-guides/evidence/refine-style/` に固有の規約。共通規約は [`output-contract.md`](./output-contract.md) を参照する。**統合の担当観点が refine-style のときだけ読む。**

## 扱う対象

AI草稿と人間による編集との差分から確認できる修正傾向を扱う。

主な対象：

- 情報の追加と削除
- 説明順の変更
- 表現の書き換え
- 段落や見出しの変更
- AIらしい定型表現の除去
- 説明の粒度調整
- 技術的修正と文体修正の分類

完成記事だけから推測した特徴は、このファイルの根拠にしない。

## 追加できる項目

共通の基本形式に加えて、次を使ってよい。

```markdown
- 修正前の特徴：
- 修正後の傾向：
- 修正操作：
- 修正の目的：
- 差分の種類：
```

意味のある情報がない項目は省略する。

## 必須要素

最低限、次を含める。

- ガイドの目的
- 修正時の基本方針
- 追加する傾向
- 削除する傾向
- 並べ替える傾向
- 書き換える傾向
- 構成を変更する傾向
- 技術説明を修正する傾向
- AIらしい文章を除去する基準
- 条件付きの修正
- 修正手順
- 一般化しない修正

修正傾向は、Git差分によって確認できるものを根拠とする。

## 根拠の書き方

`evidence/refine-style/<slug>.md` の支持行には、本文中の該当箇所ではなく**修正前後のコミット対**を書く。

```markdown
- RS-023（16758df→78ba48c：交点が偶数個になる理由の段落を新設）
```

差分の生ログは含めない。

## この観点だけの制約

**Git 履歴（AI草稿コミット）を持たない記事では、この観点を分析しない。** 根拠モード・発見モードのいずれでも、`gitAnalyzable` が空の回は Revision Diff Analyst の系列（分析・反証・統合）を起動しない。「確認できないと明記する」だけの成果物を作らせない。したがって `evidence/refine-style/` の記事数は他観点より少なくなる（欠落ではない）。

根拠には性質の異なる2系統が混在する。この違いが確度と適用範囲を左右する（詳細は `evidence/refine-style/_README.md`）。

- **実際のAI草稿→人手編集の差分**：`[ai-draft]` を含むコミットでAI生成文が記録され、その後に人手編集が重なっている記事から採れる差分。**AIらしいメタ足場・自己言及・冗長な再要約の除去を根拠にできるのはこの系統だけ。**
- **著者自身の自己改稿（下書き→推敲）の差分**：AI草稿が存在しない記事。ここから採れるのは、箇条書きメモの散文化、因果・目的の補足追加、記法・用語の統一といった推敲操作に限る。

**差分の増減行数を、圧縮・加筆の量的な根拠にしない。** 著者は箇条書きのメモをHTMLコメントとして本文に残したまま散文化させ、公開時の推敲コミットで一括削除する運用をとることがある。削除行数の相当部分がメモであり、散文の圧縮量とは対応しない。`draft: true` の除去も同様にメタデータ操作として文体修正から分離する。

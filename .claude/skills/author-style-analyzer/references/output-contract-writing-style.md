# Output Contract: writing-style

`writing-guides/writing-style.md` と `writing-guides/evidence/writing-style/` に固有の規約。共通規約は [`output-contract.md`](./output-contract.md) を参照する。**統合の担当観点が writing-style のときだけ読む。**

## 扱う対象

文章の構成として観察できる傾向を扱う。

主な対象：

- 記事全体の情報配置
- 導入から本題への移行
- セクションの分割と接続
- 段落の構造
- 一文の情報量
- 定義、理由、例、注意点の配置
- 記事タイプによる構成の変化

内面的な意図や頻出表現は、主な対象にしない。

## 追加できる項目

共通の基本形式に加えて、次を使ってよい。

```markdown
- 配置位置：
- 前後の要素：
- 記事タイプ：
- 構成上の効果：
```

`前後の要素` / `構成上の効果` は、`ルール` 欄・適用条件欄の言い換えになるなら書かない。

## 必須要素

最低限、次を含める。

- ガイドの目的
- 全体構成
- 導入
- セクション構成
- 段落構成
- 文の構成
- 定義と例の配置
- 補足や注意事項
- 記事タイプによる変化
- 生成時のガイドライン
- 避ける構成

## 根拠の書き方

`evidence/writing-style/<slug>.md` の支持行には、本文中の該当箇所を短く添える。

```markdown
- WS-004（末尾を結果要約「なめらかに見えるようになります」で閉じる）
```

配置の型そのものは日本語の技術文書一般と重なるため、確度の上限に次を反映する（詳細は `evidence/writing-style/_README.md`）。

- 「総論→各論」「定義先行」「単純→複雑」「末尾要約」などの型自体は普遍的な構成術であり、確度を上げる根拠にしない。著者固有性は、その型をどこまで徹底するかに置く
- CardGrid／TermCard／`:WithGradeTag` などに依存する配置は、機械的運用と著者判断を切り分けられないため確度を抑える
- 総括節の不在のような「不在」の観察は、媒体条件による説明を排除できない。異なるジャンルで再確認できた場合にのみ、慣習だけには帰せないと判断する

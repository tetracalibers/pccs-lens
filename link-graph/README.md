# link-graph

記事本文（`app/src/routes/**/+page.svx`）どうしの**内部リンクをネットワークグラフとして可視化する**ローカル専用ツール。

「本文が書かれていないページにリンクが張られている箇所」を一望して、**赤いノードから順に潰していく判断材料**を得るために使う。app からは完全に独立していて（`app` を読み取るだけ・依存も `link-graph/` 内で完結）、公開ビルドには一切関わらない。

## 使い方

```sh
cd link-graph
npm install     # 初回のみ（cytoscape, cytoscape-bubblesets, d3-force, yaml, vite）
npm run dev     # http://localhost:5174 が開く
```

`.svx` を保存すると自動で再走査され、画面が更新される（既存ノードの位置は維持され、増えた分だけが落ち着く）。app の dev サーバー（`http://localhost:5173`）も上げておくと、サイドパネルの「記事を開く」からその記事へ飛べる。

### 画面

| 場所           | 中身                                                                                                            |
| -------------- | --------------------------------------------------------------------------------------------------------------- |
| ヘッダー       | 件数の集計（ページ / 本文なし / draft / 公開済 / リンク切れ / リンク / エッジ）と最終走査時刻、「再配置」ボタン |
| 左サイドバー   | フィルタ（大分類 → ユニット → 孤立ページ）と凡例                                                                |
| 中央           | グラフ。ドラッグで移動、スクロールで拡大縮小、ノードのクリックで詳細、ノードのドラッグで配置を動かす            |
| 右サイドパネル | 選択したページの状態・被リンク元・リンク先・記事へのリンク                                                      |

ノードの塗り色は**ページの状態**、エッジの色は**リンク先の状態**で決まる。

| 色             | 意味                                                                     |
| -------------- | ------------------------------------------------------------------------ |
| マゼンタ（大） | リンク切れ（`+page.svx` も `+page.svelte` も実在しない）。囲みの外に置く |
| 赤             | 本文なし（フロントマター以降が `## TODO` のみ）                          |
| 黄             | 本文はあるが `draft: true`                                               |
| 灰             | 公開済                                                                   |
| 薄いゴースト   | OFF にした大分類のページのうち、ON 側からリンクされている先              |

ノードのラベル（記事タイトル）は**常時オン**。引いて文字が小さくなりすぎたら Cytoscape が自動で落とす（`theme.js` の `LABEL_MIN_ZOOMED_FONT_SIZE`。下げるほど引いた状態でも見える）。落ちている状態でも、**ホバー**したノードと、**選択**したノードの周辺は必ずラベルが出る。

ユニットの囲みは **BubbleSets の輪郭**で描く。メンバーのノードとエッジが張る影響場の等値線なので、ノードが動けば囲みの形も追いかけて変わる。**囲み自体にはラベルを付けない** — どのユニットかは左のフィルタと、ノードを選んだときのサイドパネルの所属バッジで分かる。

### フィルタ

- **大分類**（色の理論 / 色の活用分野 / CGと画像処理）… 起動時は「CGと画像処理」のみ ON
- **ユニット**（囲みの単位）… ON になっている大分類の分だけ下段に出る。ページが 0 件のユニットは出さない
- **孤立ページ**（入次数・出次数がともに 0）… 起動時は非表示

OFF にした大分類のページでも、ON 側からリンクが張られている先は**ゴースト**として薄く残る（囲みの外）。色系 103 ノードで画面を占領されずに、CG 系からの依存先だけが見える状態にするため。

フィルタの設定は**永続化しない**。開くたびに上のデフォルトから始まる。

### 走査だけ実行する

グラフを描かずに集計だけ見たいとき、JSON をパイプで加工したいとき:

```sh
npm run scan            # 集計サマリを表示
npm run scan -- --json  # グラフデータ（JSON）をそのまま出力
```

dev サーバー起動中は `http://localhost:5174/api/graph` でも同じ JSON が取れる。

## 走査のルール

### 対象ページ

`app/src/routes/**/+page.svx` のうち、次の 3 グループのいずれかのユニットに属する記事ページだけ。

| グループ     | ルート                  | ユニットの決め方                                                       |
| ------------ | ----------------------- | ---------------------------------------------------------------------- |
| 色の理論     | `/color-theory/<slug>/` | `app/src/lib/content-pages/color-theory.yaml` のカテゴリ（`id`）       |
| 色の活用分野 | `/color-fields/<slug>/` | `app/src/lib/content-pages/color-fields.yaml` のカテゴリ（`id`）       |
| CGと画像処理 | `/cg/<unit>/<slug>/`    | ルートのパスセグメント（= `app/src/lib/content-pages/cg/<unit>.yaml`） |

`/concept/` は `.svx` だがどのユニットにも属さないため対象外（リンク元としても数えない）。

### リンクの抽出

本文中の `[文言](/path/)` 形式のルート相対リンクを拾う。ただし次の中は本文ではないので**すべて除外**する。

- `:::Pending`（採否を検討中の文章）
- `:::Add` / `:::Fix` / `:::Delete`（編集指示メモ）
- `:::Todo`（図版・デモの未実装プレースホルダ）
- コードブロック（` ``` `）

リンク先の扱い:

- `+page.svx` が実在して対象ページ → エッジを張る
- `+page.svelte` が実在（一覧ページ、`/jis-color-map/` などのツールページ。動的ルート `[slug]` も解決する） → 意図的なリンクとしてグラフから除外
- どちらも実在しない → **リンク切れノード**として囲みの外に表示

同一ペアの複数リンクは 1 本に束ね、相互リンク（A→B と B→A）は双方向の矢印 1 本に潰す。双方向エッジの色は両端を見て強い方（リンク切れ > 赤 > 黄 > 通常）を採る。

### 依拠している規約

ページの状態判定は、`create-cg-page` / `create-color-theory-page` / `create-color-fields-page` スキルが生成する雛形（`## TODO` のみ）と、`publish-article` スキルが外す `draft: true` に依拠している。除外するディレクティブは `apply-edit-requests` スキルが扱うものと同一。**これらのスキルの規約が変わったら、`scan/config.mjs` の定数を追随させる必要がある。**

### 配置について

配置は **d3-force のシミュレーション**（`simulation.js`）が持ち、毎フレームその座標を Cytoscape へ流し込む。力は 4 つで、最後の 1 つだけ自前の実装。

| 力       | 中身                                                         |
| -------- | ------------------------------------------------------------ |
| `charge` | ノード同士の反発（`forceManyBody`）                          |
| `link`   | エッジによる引力（`forceLink`）                              |
| `center` | 全体を原点へ寄せる弱い引力（`forceX` / `forceY`）            |
| `unit`   | 同じユニットを重心へ引き、ユニットの重心どうしは離す（自前） |

`unit` がないと、同じユニットのページが必ずしも近くに来ないので囲みが伸びきってしまう。`charge` との綱引きなので、強いと団子になってリンク構造が読めず、弱いと囲みが散る。数値は全て `theme.js` の `SIMULATION` にある。

#### 動かすタイミング

**常時シミュレーションにはしていない。** 走査やフィルタのたびに全体が泳ぐと「さっき見ていた赤がどこへ行ったか」を追えなくなるうえ、配置が決まるまでの過程を描くとチラつく。そこで、**配置の計算はすべて裏で解き切って、結果だけを描く**。

| きっかけ                              | 挙動                                                                         |
| ------------------------------------- | ---------------------------------------------------------------------------- |
| 初回ロード                            | ユニットごとの中心（円周上のスロット）から**裏で**解き切って、結果だけを描く |
| フィルタの変更・再走査（`.svx` 保存） | 増えた分だけを**裏で**落ち着かせて、結果だけを描く。減っただけなら動かさない |
| 「再配置」ボタン                      | 初回と同じ。ユニットの中心から解き直して、結果だけを描く                     |
| ノードのドラッグ後                    | 離した位置を起点に、周りだけが小さく揺り戻す（**動くのはここだけ**）         |

「裏で」は d3 の `simulation.tick()` のこと。tick イベントを飛ばさないので途中の状態は Cytoscape へ渡らず、**中間フレームが 1 枚も描かれない**。実データでの実測は、初回（CG 系のみ 66 ノード）で 47ms、色系も ON にして 103 ノード増えたときで 59ms。

フィルタの変更・再走査では、**生き残ったノードを現在の座標に固定**（d3 の `fx`/`fy`）してから解くので、既存ノードの移動量は 0 px。固定は解き終えた時点で外すので、次のドラッグには周りが反応する。

初期配置のばらけと d3-force 内部の jiggle は `simulation.randomSource` にシード付きの擬似乱数（`theme.js` の `SIMULATION_SEED`）を差してあるので、同じ走査結果からは毎回同じ配置に落ち着く。

ドラッグ後の揺り戻しだけは rAF で回すので、その間は「再配置」ボタンが「停止」に変わる（押せばその場で固定できる）。動いている間は**ラベルを落とす**（`graph.js` の `.no-label`）。流れる文字は読めないうえ、169 ノード分のテキスト描画が毎フレーム乗ると重い。

### 囲みの形について

`cytoscape-bubblesets` を使う。compound node の外接矩形ではなく、**メンバーのノードとエッジが張る影響場（ポテンシャル）の等値線**なので、枝の伸びた方向へ囲みも伸びる。輪郭は `cytoscape-layers` がノードレイヤーの下に挿した SVG レイヤーに、1 ユニット 1 本の `path` として出る。

更新の引き金はメンバーの `position` イベントで、プラグイン側が `throttle`（`theme.js` の `HULL_OPTIONS`）で間引く。**毎フレーム再計算はしない** — BubbleSets はピクセルグリッド上のマーチングなので安くはなく、間引くことで負荷を抑えつつ、囲みがノードから少し遅れて追従する粘性のある動きになる。重いときは `pixelGroup`（グリッドの粗さ）を上げ、`throttle` を伸ばす。

`nodeR0` / `nodeR1` が影響場の内径・外径で、これが実質の「囲みの余白」になる。離れたメンバーが複数の島に割れないよう `virtualEdges` を立てている（プラグイン側の既定は `false`）。

囲みどうしが重ならない保証はない。表示するユニットが増えると（色の理論を ON にするなど）重なりは避けられないので、塗りは薄い半透明・輪郭ははっきりめにして、重なっていても 1 つ 1 つの形を目で追えるようにしてある。

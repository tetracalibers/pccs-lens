# link-graph

記事本文（`app/src/routes/**/+page.svx`）どうしの**内部リンクをネットワークグラフとして可視化する**ローカル専用ツール。

「本文が書かれていないページにリンクが張られている箇所」を一望して、**赤いノードから順に潰していく判断材料**を得るために使う。app からは完全に独立していて（`app` を読み取るだけ・依存も `link-graph/` 内で完結）、公開ビルドには一切関わらない。

## 使い方

```sh
cd link-graph
npm install     # 初回のみ（cytoscape, d3-force, yaml, vite）
npm run dev     # http://localhost:5174 が開く
```

`.svx` を保存すると自動で再走査され、画面が更新される（既存ノードの位置は維持され、増えた分だけが落ち着く）。app の dev サーバー（`http://localhost:5173`）も上げておくと、サイドパネルの「記事を開く」からその記事へ飛べる。

### 画面

| 場所           | 中身                                                                                                                                                                                                                                 |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ヘッダー       | 件数（ページ / 本文なし / 執筆中 / 公開済 / 孤立 / リンク切れ）と最終走査時刻、「再配置」ボタン。**件数は左サイドバーで選択中のページだけを数える。** 本文なし・執筆中・公開済・孤立・リンク切れ・自己リンクはクリックで絞り込みになる |
| 左サイドバー   | フィルタ（大分類 → ユニット）と凡例                                                                                                                                                                                                  |
| 中央           | グラフ。ドラッグで移動、スクロールで拡大縮小、ノードのクリックで詳細                                                                                                                                                                 |
| 右サイドパネル | 選択したページの状態・そのページへのリンク・そのページが含むリンク・記事へのリンク                                                                                                                                                   |

ノードの塗り色は**ページの状態**、エッジの色は**リンク先の状態**で決まる。

| 色                   | 意味                                                                          |
| -------------------- | ----------------------------------------------------------------------------- |
| 濃い赤（大・L\* 30） | リンク切れ（`+page.svx` も `+page.svelte` も実在しない）                      |
| 朱（L\* 56）         | 本文なし（フロントマター以降が `## TODO` のみ）                               |
| 山吹（L\* 77）       | 執筆中（本文はあるが `draft: true`）                                          |
| 濃い青緑（L\* 46）   | 公開済                                                                        |
| 薄いグレー           | 非表示ノードへのリンク（OFF にした大分類のうち、ON 側からリンクされている先） |

状態色は**色相ではなく明度で段をつけている**。以前はリンク切れをマゼンタ・本文なしを朱にしていたが、明度がほぼ同じ（L\* 47 と 50）で違いが色相だけだったため、11〜20px の点では見分けがつかなかった。色相は小さな点でいちばん先に潰れる手がかりなので、暖色系のまま L\* を 30 / 56 / 77 と離してある。公開済だけは異常系の暖色と系統を分けて青緑（L\* 46）に置いている。**ゴーストは状態の色を薄めるのではなく、専用のグレー**（`theme.js` の `GHOST_COLOR`）にしてある。ゴーストが伝えるのは「いま画面に出ていない先を指している」ことだけで、その先が本文なしか執筆中かは（表示していないので）読み取れなくてよい。無彩色にしておくと状態色のどれとも競合せず、色の意味が「異常＝暖色 / 公開済＝青緑 / 画面外＝グレー」で揃う。実効色（グレーを 0.4 で重ねた `#ced4dd`）との ΔE は、公開済 38・本文なし 40・執筆中 35・リンク切れ 57。エッジも同じ色相のまま「L\* を +10・彩度を 65%」で作るので、線にも同じ段が乗る。

ノード色は点として見たときの見分けやすさで決めているので、そのまま小さな文字に使うとコントラストが足りない（山吹は白地 1.86:1）。ヘッダーのチップの数字とサイドパネルのバッジの文字だけは、色相を保って L\* を下げた**文字用の濃い版**（`theme.js` の `STATE_TEXT_COLORS`、白地 4.5:1）を使う。「孤立」の数字だけは状態ではないので状態色の系統に混ぜず、**青**（`ISOLATED_TEXT_COLOR`、L\* 39・C\* 83・白地 6.7:1）を単独で置く。濃紺まで沈めると 12px では黒との差が ΔE 19 しか無く「青」と読めないので、彩度を上げて明度も上げてある。

ノードのラベル（記事タイトル）は**常時オン**。引いて文字が小さくなりすぎたら Cytoscape が自動で落とす（`theme.js` の `LABEL_MIN_ZOOMED_FONT_SIZE`。下げるほど引いた状態でも見える）。落ちている状態でも、**ホバー**したノードと、**選択**したノードの周辺は必ずラベルが出る。ラベルどうしが縦に重なって読めなくなるのは配置の側で防ぐ（→ [ラベルの縦重なり](#ラベルの縦重なり)）。

**ユニットの囲みは描かない。** 同じユニットのページは配置の力（→ [配置について](#配置について)）で近くに集まるので、かたまりとしては読める。どのユニットかは左のフィルタと、ノードを選んだときのサイドパネルの所属バッジで分かる。

### フィルタ

- **大分類**（色の理論 / 色の活用分野 / CGと画像処理）… 起動時は「CGと画像処理」のみ ON
- **ユニット**… ON になっている大分類の分だけ下段に出る。ページが 0 件のユニットは出さない

**孤立ページ**（入次数・出次数がともに 0）は左サイドバーでは扱わない。常に表示して、見たいときだけヘッダーの「孤立」チップで絞り込む。配置を動かさずに出し入れできるほうが、「どのかたまりの外に浮いているか」を掴みやすいため。

OFF にした大分類のページでも、ON 側からリンクが張られている先は**ゴースト**として薄く残る（ユニットには寄せない）。色系 103 ノードで画面を占領されずに、CG 系からの依存先だけが見える状態にするため。

フィルタの設定は**永続化しない**。開くたびに上のデフォルトから始まる。

### ヘッダーの件数

**件数は左サイドバーで選択されているページだけから数える**（`main.js` の `countSelected`）。走査結果の全体集計（`data.stats`）は使わない。全体の数を出すと、たとえば「自己リンク 1」と表示されているのに CG 系だけを選んでいると該当ノードが 1 つも無く、**押しても何も起きないチップ**になる。件数 0 の異常チップ（所属不明・自己リンク）は出さないので、選択によって現れたり消えたりする。

母集団は左サイドバーのトグル（大分類・ユニット）を通ったページ（`plan.primary`）で、**ゴーストは数えない**（画面外への依存を示す点で、状態を読み取らせる意図が無いため）。「リンク切れ」だけは選択中のページから張られている先（`plan.broken`）を数える。

0 件のときに消すかどうかは、**押せるかどうか**で分ける。**絞り込みのトグルになっているチップ（本文なし / 執筆中 / 公開済 / 孤立 / リンク切れ / 自己リンク）は 0 でも常設する** — 件数が選択中のページから数えたものなので 0 は「ここには無い」という情報になるし、選択を変えるたびにトグルが現れたり消えたりすると探し直しになる。**押せない警告チップ（所属不明）だけは 0 なら出さない** — 無いのが正常な項目で、常設しても読むものが無いため。

**ヘッダーのチップでの絞り込み自体は母集団に入れない。** 入れると「本文なし」を押した瞬間に執筆中と公開済が 0 になって、トグルとして読めなくなる。

### ヘッダーのチップでの絞り込み

ヘッダーの**本文なし・執筆中・公開済・孤立・リンク切れ・自己リンク**はクリックできる。押すと、該当しないノードとその線が消える（複数押せば OR）。もう一度押すと戻る。

左のフィルタとの違いは、**配置を一切動かさない**こと。シミュレーションのノードからは外さず、要素はそのまま置いたまま透明にして当たり判定を切るだけなので、ノードの座標は 1 px も動かない。押して戻せば元の絵に完全に戻る。

### 走査だけ実行する

グラフを描かずに集計だけ見たいとき、JSON をパイプで加工したいとき:

```sh
npm run scan            # 集計サマリを表示
npm run scan -- --json  # グラフデータ（JSON）をそのまま出力
```

dev サーバー起動中は `http://localhost:5174/api/graph` でも同じ JSON が取れる。

## 走査のルール

### 対象ページ

`app/src/routes/**/+page.svx` のうち、次の 3 グループのいずれかのユニットに属する記事ページだけ。

| グループ     | ルート                  | ユニットの決め方                                                       |
| ------------ | ----------------------- | ---------------------------------------------------------------------- |
| 色の理論     | `/color-theory/<slug>/` | `app/src/lib/content-pages/color-theory.yaml` のカテゴリ（`id`）       |
| 色の活用分野 | `/color-fields/<slug>/` | `app/src/lib/content-pages/color-fields.yaml` のカテゴリ（`id`）       |
| CGと画像処理 | `/cg/<unit>/<slug>/`    | ルートのパスセグメント（= `app/src/lib/content-pages/cg/<unit>.yaml`） |

`/concept/` は `.svx` だがどのユニットにも属さないため対象外（リンク元としても数えない）。

### リンクの抽出

本文中の `[文言](/path/)` 形式のルート相対リンクを拾う。ただし次の中は本文ではないので**すべて除外**する。

- `:::Pending`（採否を検討中の文章）
- `:::Add` / `:::Edit` / `:::Modify` / `:::Delete`（編集指示メモ）
- `:::Todo`（図版・デモの未実装プレースホルダ）
- コードブロック（` ``` `）

リンク先の扱い:

- `+page.svx` が実在して対象ページ → エッジを張る
- `+page.svelte` が実在（一覧ページ、`/jis-color-map/` などのツールページ。動的ルート `[slug]` も解決する） → 意図的なリンクとしてグラフから除外
- どちらも実在しない → **リンク切れノード**として表示（ユニットには寄せない）

同一ペアの複数リンクは 1 本に束ね、相互リンク（A→B と B→A）は双方向の矢印 1 本に潰す。双方向エッジの色は両端を見て強い方（リンク切れ > 赤 > 黄 > 通常）を採る。

### 依拠している規約

ページの状態判定は、`create-cg-page` / `create-color-theory-page` / `create-color-fields-page` スキルが生成する雛形（`## TODO` のみ）と、`publish-article` スキルが外す `draft: true` に依拠している。除外するディレクティブは `apply-edit-requests` スキルが扱うものと同一。**これらのスキルの規約が変わったら、`scan/config.mjs` の定数を追随させる必要がある。**

### 配置について

配置は **d3-force のシミュレーション**（`simulation.js`）が持ち、毎フレームその座標を Cytoscape へ流し込む。力は 4 つで、最後の 1 つだけ自前の実装。

| 力       | 中身                                                         |
| -------- | ------------------------------------------------------------ |
| `charge` | ノード同士の反発（`forceManyBody`）                          |
| `link`   | エッジによる引力（`forceLink`）                              |
| `center` | 全体を原点へ寄せる弱い引力（`forceX` / `forceY`）            |
| `unit`   | 同じユニットを重心へ引き、ユニットの重心どうしは離す（自前） |

`unit` がないと、同じユニットのページが必ずしも近くに来ないので、かたまりとして読めなくなる。`charge` との綱引きなので、強いと団子になってリンク構造が読めず、弱いとユニットが散る。数値は全て `theme.js` の `SIMULATION` にある。

#### ラベルの縦重なり

力で解き切ったあと、**ラベルが縦に重ならないように `y` だけを掃き分ける**（`declutter.js`）。

ノード同士の当たり判定（`forceCollide`）は円なので、「縦は近いが横は遠い」と「縦も横も近い」を区別できない。ところがラベルはノードの右横に出る 1 行のテキストで、実体は**幅 100px 前後・高さ 16px の扁平な箱**（169 ページのタイトルは中央値 9 文字・最大 19 文字）。ノードの間隔（中心間 25px 前後）よりラベルのほうがはるかに横長なので、横位置はほとんどの組で重なっていて、読めるかどうかは縦の間隔だけで決まっている。

**全ノードに一律の縦間隔は与えない。** 169 ノード × 16px = 2700px の縦帯になり、レイアウト全体（1300px 角）より縦に伸びて、ユニットのかたまりが読めなくなる。ほどくのは**箱が横方向でも重なっている組だけ**で、それ以外は縦にいくら近くてもよい。手順は 2 段。

| 段    | 中身                                                                                                                |
| ----- | ------------------------------------------------------------------------------------------------------------------- |
| relax | 重なっている組を上下へ半分ずつ押し合う。全体が片側へ寄らないよう、大半をここで解消する                              |
| sweep | 上から順に置き直し、残った重なりを下へ逃がす。置いたノードは以降動かさないので、この 1 巡で**全ての組が保証される** |

`x` は 1px も動かさないので、横方向の構造は変わらない。実データでの実測（ラベル幅は全角 11px 換算）は次の通りで、縦に伸びるのは 1% 台に収まる。

| 表示                  | ラベルが重なる組 | レイアウトの広さ      | 縦のずれ（中央値 / 最大） | 所要 |
| --------------------- | ---------------- | --------------------- | ------------------------- | ---- |
| CG のみ（65 ノード）  | 28 → 0           | 630×866 → 630×879     | 3.6px / 31.6px            | 2ms  |
| 全部 ON（169 ノード） | 61 → 0           | 1309×1265 → 1309×1267 | 1.4px / 15.4px            | 2ms  |

固定（`fx`/`fy`）されたノードは動かさないので、**増えた分だけを落ち着かせるときに既存ノードがずれることはない**（実測 0px）。ヘッダーのチップで絞り込まれているノードも対象に含める — 絞り込みは配置に触らない決まりなので、絞り込むたびに縦の間隔が変わってはいけない。

箱の高さの根拠と反復回数は `theme.js` の `LABEL_SEPARATION` にある。ラベルの実寸は Cytoscape と同じ手（canvas の `measureText`）で測るので、描かれる幅と一致する（`labels.js`。フォントの指定は `theme.js` の `LABEL_FONT_FAMILY` を描く側と測る側で共有する）。

#### 動かすタイミング

**アニメーションは一切しない。** 走査やフィルタのたびに全体が泳ぐと「さっき見ていた赤がどこへ行ったか」を追えなくなるうえ、配置が決まるまでの過程を描くとチラつく。そこで、**配置の計算はすべて裏で解き切って、結果だけを描く**。動いているフレームは 1 枚も無い。

| きっかけ                              | 挙動                                                                         |
| ------------------------------------- | ---------------------------------------------------------------------------- |
| 初回ロード                            | ユニットごとの中心（円周上のスロット）から**裏で**解き切って、結果だけを描く |
| フィルタの変更・再走査（`.svx` 保存） | 増えた分だけを**裏で**落ち着かせて、結果だけを描く。減っただけなら動かさない |
| 「再配置」ボタン                      | 初回と同じ。ユニットの中心から解き直して、結果だけを描く                     |

「裏で」は d3 の `simulation.tick()` のこと。tick イベントを飛ばさないので途中の状態は Cytoscape へ渡らず、**中間フレームが 1 枚も描かれない**。実データでの実測は、初回（CG 系のみ 66 ノード）で 47ms、色系も ON にして 103 ノード増えたときで 59ms。

フィルタの変更・再走査では、**生き残ったノードを現在の座標に固定**（d3 の `fx`/`fy`）してから解くので、既存ノードの移動量は 0 px。

初期配置のばらけと d3-force 内部の jiggle は `simulation.randomSource` にシード付きの擬似乱数（`theme.js` の `SIMULATION_SEED`）を差してあるので、同じ走査結果からは毎回同じ配置に落ち着く。

**ノードをドラッグして手で動かすことはできない**（Cytoscape の `autoungrabify`）。配置はシミュレーションが決めるもので、手で置き直せてもその位置に意味が無く、離した先で周りが揺り戻す動きも「さっき見ていた点を見失う」方向に働くため。背景のドラッグでのパンとスクロールでのズームはそのまま効く。
